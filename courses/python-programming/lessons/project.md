## 脚本结构与调试

在编写工业数据处理脚本时，良好的程序结构能显著降低出错率并提高维护效率。
初学者常把代码全部平铺在文件顶层，导致变量互相干扰、无法单独测试且难以复用。
规范的工程脚本应当将不同功能的逻辑封装为独立函数，并使用主入口进行协调。

### 1. 主入口与 __name__ 机制

Python 文件既可以作为独立程序直接执行，也可以作为模块被其他文件导入（import）。
Python 解释器在加载文件时会自动维护内置变量 __name__：
- 当脚本在终端被直接运行时，__name__ 的值会被自动赋值为字符串 "__main__"；
- 当脚本被其他文件通过 import 语句导入时，__name__ 的值则是该模块自身的文件名。

为了避免脚本被其他程序导入时自动执行耗时的数据处理流程，通常将核心流程放入
名为 main() 的函数中，并在文件末尾使用条件判断作为主入口：

```python
def main():
    print("分拣记录处理系统启动")

if __name__ == '__main__':
    main()
```

运行结果：
```text
分拣记录处理系统启动
```

### 2. 函数单一职责拆分

编写高质量脚本的关键原则是“一个函数只做一件事”。处理检测记录时，建议拆分为：
- 数据读取与跳过表头；
- 单行记录合法性验证与解析；
- 有效记录指标统计；
- 统计报告格式化输出。

拆分后的函数一般控制在 30 行以内，接受明确的参数并返回处理结果。当某项业务逻辑
发生变化（例如判定标准调整）时，只需修改对应函数，而不会牵动整个程序的结构。

### 3. print 插桩调试与 Traceback 排查

在代码运行结果不符合预期或报错中断时，需要掌握两项核心调试技巧：

- print 变量插桩：在关键的分支判断前、循环体内部和计算节点，使用 print 输出
  当前变量名和对应值。例如 print(f"DEBUG row_index={idx}, status={status}")。
  排查完成后应及时清理插桩代码，保持控制台整洁。
- Traceback 从下向上阅读：当程序抛出未捕获异常退出时，控制台会输出调用栈回溯。
  阅读回溯信息时，应首先查看最底下一行的异常类型（如 ValueError）和具体描述，
  再向上看紧邻的前一行，找到引发异常的具体文件名与代码行号，快速定位问题根源。

### 例题

编写一个用于校验工件尺寸并统计合格情况的小脚本，要求将单件校验与汇总逻辑
拆分为独立函数，并采用规范的主入口结构。

解答：

```python
def check_dimension(item_id, value_str):
    try:
        val = float(value_str)
        if 11.90 <= val <= 12.10:
            return True, "PASS"
        return True, "REJECT"
    except ValueError:
        return False, f"工件 {item_id} 尺寸格式非法: {value_str}"

def process_batch(records):
    pass_cnt = 0
    reject_cnt = 0
    errors = []
    for item_id, val_str in records:
        valid, result = check_dimension(item_id, val_str)
        if valid:
            if result == "PASS":
                pass_cnt += 1
            else:
                reject_cnt += 1
        else:
            errors.append(result)
    return pass_cnt, reject_cnt, errors

def main():
    test_data = [
        ("P01", "12.02"),
        ("P02", "11.85"),
        ("P03", "N/A"),
        ("P04", "12.05"),
    ]
    p_cnt, r_cnt, errs = process_batch(test_data)
    print(f"合格数: {p_cnt}, 拒收数: {r_cnt}")
    print(f"异常项: {errs}")

if __name__ == '__main__':
    main()
```

运行结果：
```text
合格数: 2, 拒收数: 1
异常项: ['工件 P03 尺寸格式非法: N/A']
```

例题分析：
脚本将单条记录的数值解析与范围检查放在 check_dimension 函数中，遇到不可转为
浮点数的脏数据时返回异常提示；process_batch 函数专注于遍历与聚合统计；main 函数
负责准备测试数据与输出结果。各函数输入输出清晰，逻辑易于验证与单步调试。

### 常见错误

1. 全局平铺代码：未将业务流程放入函数中，所有变量暴露在全局命名空间，造成逻辑
   耦合且无法单独导入测试。
2. 逆向阅读 Traceback：面对报错回溯时从顶部逐行向下寻找，被多层调用堆栈迷惑，
   忽略了最底部给出的精确异常类型与出错代码行号。
3. 盲目修改代码：程序输出异常时不进行 print 插桩观察中间数据，凭空猜测错误原因，
   容易越改越乱引入新的隐蔽缺陷。

## 检测记录统计脚本（自评）

目标：
编写一个 Python 脚本，读取桌面质检分拣站保存的工件检测记录 CSV 文件，
逐行解析工件编号与判定结果；识别并收集格式异常或数据缺失的记录行；
分别统计有效工件的合格数与拒收数，并在终端打印结构清晰的汇总报表；
最后利用测试样本手工计算核验统计结果。

材料或准备：
1. 运行环境：Python 3.12 解释器及命令行终端。
2. 测试数据文件：在工作目录下创建名为 inspection_records.csv 的文本文件，
   内容包含正常数据、空值行与非法判定状态：
```text
part_id,result,timestamp
P201,PASS,2026-11-13 09:00:15
P202,REJECT,2026-11-13 09:00:28
P203,,2026-11-13 09:00:42
,PASS,2026-11-13 09:00:55
P204,ERROR,2026-11-13 09:01:10
P205,PASS,2026-11-13 09:01:25
```

步骤：

步骤 1：规划脚本结构与函数职责。
新建脚本 inspection_summary.py。定义 parse_record(row, line_no) 负责解析单行，
summarize_records(filepath) 负责文件读取与聚合，main() 负责运行流程与格式化展示。

步骤 2：读取 CSV 并识别表头。
使用 Python 内置的 csv.reader 读取 inspection_records.csv 文件。
利用 next(reader) 读取并跳过首行表头，同时记录行号计数器以便准确报错。

步骤 3：编写单行记录验证函数。
对每一行数据进行校验：工件编号不能为空字符串；判定结果必须严格为 PASS 或
REJECT。若存在字段缺失或出现 ERROR 等未定义状态，返回错误标记、行号及具体原因。

步骤 4：循环聚合统计与异常收集。
遍历有效行，若判定结果为 PASS 则合格计数器累加 1；若为 REJECT 则拒收计数器累加 1；
对校验失败的行，将其行号与原因整理存入 unparsed_lines 列表。

步骤 5：终端报表输出与人工核对。
在 main 函数中打印总读取行数、合格总数、拒收总数，并逐一列出无法解析的行和原因。
对照原始 CSV 文件进行手工点算，确认脚本各项统计数值与手工核对结果完全一致。

## 单元小结

- 规范入口：使用 main() 与 if __name__ == '__main__': 结构，确保脚本既可直接独立运行，又可安全作为模块被调用。
- 模块化设计：遵循单一职责原则，将文件解析、业务校验与报表统计解耦为独立函数，降低维护难度。
- 高效调试：善用 print 变量插桩观察内部运行轨迹，严格按照从下向上的顺序解读 Traceback 快速锁定错误。
- 防御性统计：对工业现场采集的 CSV 数据始终进行空值与格式校验，隔离脏数据并辅助手工核对保证结果可信。
