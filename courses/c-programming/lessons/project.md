## 多文件与模块化
在单片机分拣工位程序中，若将传感器采集、舵机分拣控制和串口通信全部写在
单个源文件中，会导致代码耦合严重、难以维护和多人协同。模块化编程要求
按照硬件功能或业务逻辑将程序拆分为独立的模块。

每个模块通常由两部分组成：头文件（.h）与源文件（.c）。
- 头文件（.h）：用于向外部模块暴露接口契约，包含函数原型声明、宏定义、
  结构体类型声明以及外部变量声明，使用条件编译宏构建包含卫士以防重复包含。
- 源文件（.c）：用于存放具体的函数实现逻辑和该模块私有的全局变量。

跨文件共享全局变量时，必须在且仅在一个 .c 源文件中定义并初始化变量，
而在头文件中使用 `extern` 关键字进行引用声明。对于仅在当前模块内部
使用的辅助函数或局部全局变量，应使用 `static` 关键字修饰，
将其链接属性限制在当前文件内，避免命名污染与外部非法篡改。

### 例题
编写分拣控制模块头文件 `sorter.h` 与源文件 `sorter.c` 的核心结构。
```c
/* sorter.h */
#ifndef SORTER_H
#define SORTER_H

extern int g_total_sorted;
void sorter_init(void);
int sorter_is_pass(int weight);

#endif
```
```c
/* sorter.c */
#include "sorter.h"

int g_total_sorted = 0;
static int s_pass_threshold = 50;

void sorter_init(void) {
    g_total_sorted = 0;
}

int sorter_is_pass(int weight) {
    if (weight >= s_pass_threshold) {
        g_total_sorted++;
        return 1;
    }
    return 0;
}
```
【解答说明】`g_total_sorted` 在头文件中使用 extern 声明供外界读取，
在源文件中分配实体内存；`s_pass_threshold` 加 static 修饰，隐藏实现细节。

### 常见错误
1. 在 `.h` 头文件中直接定义变量（如 `int count = 0;`），当多个 `.c` 文件
   同时包含该头文件时，链接器会报符号重复定义（multiple definition）错误。
2. 忘记在头文件中编写 `#ifndef`、`#define` 与 `#endif` 包含卫士，
   导致复杂的头文件相互嵌套包含时引发类型重复声明错误。

## 传感器数据处理
工件在流水线上到位时，光电测距或称重传感器常伴随机械震动与电气噪声，
直接使用单次裸采样值判定工件是否合格会导致严重的误检与漏检。

滑动平均滤波（Moving Average）是工业检测中最常用的基础平滑算法：
维护一个大小为 N 的采样窗口，计算窗口内数据的算术平均值：
平均值 = (x0 + x1 + ... + x(N-1)) / N，窗口随新采样逐点前移。
该算法能平滑高频随机白噪声。在嵌入式定点运算中通常使用整除或累加定点数处理。

对于机械抖动产生的飞刺杂波，需结合异常值剔除：
- 限幅滤波：检查采样值是否超出传感器合理物理量程，超出则予以丢弃；
- 去极值滤波：采集多组数据，剔除一个最大值和一个最小值后再求均值。

在对滤波后数据进行阈值计数前，函数必须严格防御异常输入：
检查输入数据指针是否为 NULL、采样长度是否合法（大于 0），
从源头上避免程序解引用非法内存或除以零。

### 例题
编写一个带防御检查并剔除单次极大极小值的平滑求均值函数。
```c
int filter_mean(const int *buf, int len) {
    if (buf == NULL || len < 3) {
        return -1;
    }
    int max = buf[0];
    int min = buf[0];
    int sum = 0;
    for (int i = 0; i < len; i++) {
        if (buf[i] > max) max = buf[i];
        if (buf[i] < min) min = buf[i];
        sum += buf[i];
    }
    return (sum - max - min) / (len - 2);
}
```
【解答说明】函数入口先对空指针与无效长度进行拦截；一次循环中同步
统计总和与极值，最终减去最大最小值后整除计算有效均值。

### 常见错误
1. 忽略空指针与空数组判断，直接调用 `buf[0]`，引发单片机总线错误或系统崩溃。
2. 在求累加和时未考虑数据溢出，或求平均时因整除舍入导致阈值临界点判定漂移。

## 调试与常见错误
单片机开发涉及软硬件交互，清晰的排错方法是保障系统稳定运行的前提。

必须正确区分编译错误与编译警告：
- 编译错误（Error）：代码违反 C 语法规范，编译器无法生成二进制目标程序；
- 编译警告（Warning）：代码语法虽能通过，但潜藏类型隐式截断、未匹配格式串、
  未使用变量等重大隐患。工程中应开启 `-Wall -Wextra`，将警告当作错误排查。

初学者最常犯的严重运行时错误包括：
- 未初始化变量：局部非静态变量分配在栈上，其初值为内存中的随机垃圾数据，
  未初始化直接自增会导致分拣计数完全失控；
- 数组越界：C 语言不检查数组下标有效性，长度为 N 的数组合法下标为 0 到 N-1。
  越界读写会踩踏相邻变量、破坏栈帧返回地址，甚至引发 HardFault 硬件异常复位。

使用 `printf` 串口打印是工位排错的核心手段：
在状态机迁移、阈值判断分支和缓冲区写入后打印关键变量与标志字符串；
每次打印务必以换行符 `\n` 结尾；在行缓冲的输出上，换行会触发刷新，
减少程序异常复位前丢失关键日志的可能。

### 例题
分析以下存在越界与未初始化缺陷的分拣统计代码并纠正。
```c
/* 存在缺陷的代码 */
int count_pass(const int raw[], int n) {
    int pass;
    for (int i = 0; i <= n; i++) {
        if (raw[i] >= 60) pass++;
    }
    return pass;
}
```
【解答说明】该代码存在两个严重缺陷：
1. 局部变量 `pass` 未显式初始化为 0，累加结果不可预测；
2. 循环条件 `i <= n` 会访问到 `raw[n]`，导致数组越界读取。
纠正方法：将声明修改为 `int pass = 0;`，循环控制条件修正为 `i < n`。

### 常见错误
1. 在串口打印中格式占位符与参数类型不匹配（例如用 `%d` 打印指针或浮点数），
   导致打印输出乱码甚至栈空间错位。
2. 在对时间敏感的高频循环或中断中大量插入阻塞式串口打印，严重拖慢主频时序，
   破坏正常通信节拍。

## 实作：阈值计数函数与测试（自评）
目标：为桌面分拣站编写一个稳定可靠的批次质检判定函数
`int classify_batch(const int *samples, int len, int threshold, int *out_pass_count)`，
剔除量程外的异常尖峰后统计合格件数，并通过断言测试用例全覆盖验证。

材料或准备：配置好 C99 编译环境的电脑，准备包含 `<assert.h>` 与 `<stdio.h>` 的源码文件。

步骤：
1. 模块设计：创建 `inspect.h`、`inspect.c` 以及测试文件 `test_inspect.c`。
2. 接口防御：在函数头部检查 `samples == NULL`、`len <= 0` 或 `out_pass_count == NULL`，
   若参数非法直接返回 -1。
3. 算法实现：遍历工件传感器采样值，过滤明显超物理极限的无效读数（如负数读数），
   将有效值与 `threshold` 对比，合格则累加计数，将结果写入 `*out_pass_count` 并返回 0。
4. 编写白盒测试：在 `test_inspect.c` 中使用 `assert` 覆盖全合格、全不合格、
   刚好等于阈值临界点、包含异常负值工件以及空指针防护用例。
5. 编译执行：运行测试程序，观察所有断言通过且控制台无报错输出。

## 单元小结
- 模块化设计遵循“声明在 .h、实现在 .c”，全局变量用 extern 导出，内部接口用 static 隐藏。
- 传感器数据处理必须结合滤波算法抑制机械抖动，并在数据入口严密防范空输入。
- 严防局部变量未初始化与数组越界两大陷阱，善用带换行符的 printf 定位执行轨迹。
- 编写健壮的代码离不开完备的测试驱动，断言测试是保证工位程序高可靠运行的基础。
