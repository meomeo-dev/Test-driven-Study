# 指针、结构体与位运算

本单元围绕桌面分拣站的硬件控制与数据管理，讲解内存地址访问、复合数据封装、
底层状态位操作以及工程规范。

## 本单元知识点
- 指针与地址：理解内存地址概念，掌握取地址、解引用及指针传参修改外部变量。
- 指针、数组与传参：理解数组名退化规则，掌握指针算术与只读 const 指针保护。
- 结构体：使用 struct 组织工件属性，掌握点运算符与箭头运算符访问成员。
- 位运算与掩码：使用位运算符对单片机寄存器和传感器状态进行置位、清零与检测。
- 常量、宏与头文件：使用 const 与宏定义硬件常量，编写标准头文件条件编译防护。

## 指针与地址

变量在内存中都占有特定起始地址与若干字节空间。通过取地址运算符 & 可以获取
变量的首地址；声明指针变量时需指定基类型（如 int *p），表示该指针指向何种
类型的数据。基类型决定了解引用时跨越的字节宽度和解析格式。

解引用运算符 * 作用于指针时，代表访问该地址上保存的实体变量。将指针作为参数
传递给函数时，函数可以通过解引用直接读取并修改调用者环境中的实参，这是 C 语言
实现“双向数据传递”与多值返回的核心手段。

未初始化的局部指针存储的是随机垃圾地址（野指针），直接解引用会导致严重故障。
在指针暂无明确目标时，必须显式赋为 NULL（空指针）。在单片机传感采集中，通常
先检查指针是否为 NULL，再进行解引用操作。

### 例题
编写函数 update_sensor，接收表示传感器读数的变量地址，当读数小于 0 时
将其校正为 0，并返回是否发生了校正（1 表示校正，0 表示未校正）。

```c
int update_sensor(int *val) {
    if (val == NULL) return 0;
    if (*val < 0) {
        *val = 0;
        return 1;
    }
    return 0;
}
```
解答分析：参数 int *val 接收调用者的变量地址。通过 *val 检查原值并修改调用者
的实际变量。若传入 NULL 则安全退出，避免非法内存访问。

### 常见错误
- 声明指针后未初始化便直接使用 *p 写入数据，引发野指针越界写入。
- 混淆指针声明中的类型符 int *p 与表达式中的解引用 *p，在需要地址处误传值。
- 忘记对可能为空的指针参数做 p != NULL 检查。

## 指针、数组与传参

在 C 语言中，数组名在大多数表达式（包括函数实参传递）中会自动隐式转换为指向其
首元素的指针，这一特性称为“数组名退化”。因此，int arr[10] 作为实参传入函数
时，形参写为 int arr[] 或 int *arr 在编译层面上完全等价。

指针支持有限的算术运算。当指针 p 加上整数 n 时，实际偏移的内存字节数是
n * sizeof(*p)。C 语言规定 *(p + i) 与下标形式 p[i] 严格等价。通过指针
算术可以灵活地遍历传感器采集缓冲区。

当函数仅需读取数组数据而无需修改内容时，应将指针形参声明为 const 指针
（如 const int *buf）。编译器将强制实施只读检查，防止误修改生产线批次数据，
同时也明确了函数的接口契约。

### 例题
编写函数 calc_pass_count，接收合格标记数组首地址与长度，统计合格品数量
（标记为 1 表示合格），保证不修改原数组。

```c
int calc_pass_count(const int *records, int len) {
    int count = 0;
    for (int i = 0; i < len; i++) {
        if (*(records + i) == 1) {
            count++;
        }
    }
    return count;
}
```
解答分析：const int *records 保护输入数组只读；*(records + i) 与
records[i] 等效，按指针步长逐个检查工件质检标记。

### 常见错误
- 在函数内部对形参执行 sizeof(arr) / sizeof(arr[0]) 计算数组长度；形参已
  退化为指针，sizeof(arr) 仅得到指针本身大小（如 4 或 8 字节）。
- 指针移位超出数组合法有效区间，访问越界内存。

## 结构体

分拣工位上的每个工件通常包含工件编号、尺寸重量、质检结论等多种属性。基本类型
无法将这些异构数据归纳为一个整体，C 语言提供 struct 关键字定义结构体类型，
将不同类型的数据项组合为单个复合类型。

定义结构体变量后，使用点运算符 . 访问具体成员。当处理大批量工件时，可以声明
结构体数组（如 struct Item queue[20]），实现结构化记录的连续存储与批处理。

传递结构体给函数时，若按值传递会复制全部成员，带来额外开销。实务中普遍传递
结构体指针（如 struct Item *p）。访问指针指向的结构体成员时，使用箭头
运算符 ->（如 p->status），其语义等价于 (*p).status。

### 例题
定义表示工件信息的结构体，包含编号 id 与合格标志 is_pass。编写函数
mark_fail，通过指针将指定工件标记为不合格（0）。

```c
struct Part {
    int id;
    int is_pass;
};

void mark_fail(struct Part *item) {
    if (item != NULL) {
        item->is_pass = 0;
    }
}
```
解答分析：struct Part 封装了工件状态；mark_fail 接受结构体指针，
通过 item->is_pass = 0 直接修改目标工件的成员，高效且语法直观。

### 常见错误
- 结构体指针未解引用直接使用点运算符，如 item.is_pass（应为 item->is_pass）。
- 误写 *item.is_pass，因 . 优先级高于 *，等同于 *(item.is_pass) 导致语法报错。
- 结构体类型定义末尾遗漏必要的分号 ;。

## 位运算与掩码

单片机的 GPIO 引脚与外设状态通常映射在单个字节或字中。C 语言提供 6 种位运算符：
按位与 &、按位或 |、按位异或 ^、按位取反 ~、左移 <<、右移 >>。
位运算直接对整数的二进制补码位进行处理。

通过十六进制常数构造掩码（Mask）可以精准控制单个或多个位：
1. 置位（将第 n 位设为 1）：reg |= (1U << n)
2. 清零（将第 n 位设为 0）：reg &= ~(1U << n)
3. 取反（将第 n 位电平翻转）：reg ^= (1U << n)
4. 状态检测（判断第 n 位是否为 1）：if (reg & (1U << n))

在分拣工位控制中，到件光电传感器可能连接在某一特定引脚上（例如 Bit 2）。
读取端口寄存器后与对应掩码执行按位与，即可迅速剥离无关引脚电平，判断工件到位。

### 例题
工位状态寄存器 status 的 Bit 0 表示工件到位，Bit 1 表示分拣挡板到位。
编写代码检测工件是否到位，若到位则将挡板标志（Bit 1）置 1。

```c
unsigned char update_station(unsigned char status) {
    if (status & 0x01) {
        status |= 0x02;
    }
    return status;
}
```
解答分析：status & 0x01（即 1U << 0）提取最低位，非 0 说明工件到位；
status |= 0x02（即 1U << 1）将第二位置 1，保留其他位原状。

### 常见错误
- 混淆逻辑运算符 && / || 与按位运算符 & / |。
- 构造清零掩码时遗漏取反符号，写成 reg &= (1U << n) 导致其他无关位全被抹零。
- 位移操作位数超出变量类型位宽，或对带符号负数进行右移导致符号位扩展偏差。

## 常量、宏与头文件

在嵌入式编程中，硬件参数应避免硬编码魔法数字。const 关键字修饰的变量
具备类型安全，值在运行期不可更改。#define 预处理指令则在预编译期进行纯文本
替换，用于定义端口编号、缓冲区大小与参数宏。

使用 #define 编写带参宏时极易掉入优先级陷阱。宏参数和宏体外层必须严格添加
圆括号，例如 #define SQUARE(x) ((x) * (x))，否则在传入表达式时会导致
运算次序颠倒；同时应避免在宏参数中使用自增自减（如 i++）引起多次求值。

项目拆分为多源文件后，函数声明、结构体类型与公用宏应放入头文件（.h）。
为了避免同一头文件被间接重复包含导致的重复定义错误，头文件必须使用 include
防护指令（#ifndef、#define、#endif）将其包裹。

### 例题
编写分拣电机控制头文件 motor.h 的骨架，包含头文件防护、最大转速宏定义
以及启动函数声明。

```c
#ifndef MOTOR_H
#define MOTOR_H

#define MOTOR_MAX_SPEED 100

void motor_start(int speed);

#endif
```
解答分析：第一和第二行通过 #ifndef / #define 检查宏标记，若首次包含则
定义该标记并解析内容；后续若被再次包含则直接跳至 #endif，有效防止重定义。

### 常见错误
- 带参宏的参数和外层未加括号，如 #define ADD(a, b) a + b，在 ADD(1, 2) * 3 时先乘后加。
- 头文件保护宏名字冲突或拼写错误，导致防护失效或文件内容被意外跳过。
- 在头文件中定义变量实体（未加 extern）并赋初值，被多个 .c 包含时报多重定义符号链接错误。

## 单元小结
- 指针存储变量地址，利用解引用可在函数间双向传递数据，空指针赋 NULL 防野指针。
- 数组传参退化为首元素指针，指针偏移量依基类型自增，const 指针保护输入不被篡改。
- 结构体将异构工件属性聚合管理，结构体指针通过 -> 运算符高效访问各成员。
- 掌握按位与、或、异或及移位运算，利用掩码对硬件寄存器精准实施置位、清零与检测。
- 善用 const 与宏消除魔法数，宏定义严防运算符优先级，头文件必备条件编译防护。
