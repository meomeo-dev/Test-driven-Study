# 函数与测试

本单元学习如何将分拣工位的检测与控制逻辑封装为独立函数，掌握参数传递与变量生命周期，
运用断言开展边界测试，并初探递归编程思维。

## 本单元知识点
- 函数定义、参数与返回值：掌握函数声明与定义规范、形参实参值传递机制及 return/void 用法。
- 作用域、生命周期与 static：理解局部与全局变量作用范围，掌握 static 保持局部状态机制。
- 边界输入与断言测试：学习使用 assert 宏验证输入合法性，针对阈值与极值等边界用例测试。
- 递归入门：理解基准情形与递推关系，掌握阶乘计算及递归调用的栈展开过程。

## 函数定义、参数与返回值

函数是组织良好、可重用的代码模块。在分拣工位中，到位检测、尺寸判别、舵机驱动等独立
任务常被封装为独立函数。函数的标准定义包含返回值类型、函数名、形式参数列表及函数体。
若函数无需向调用者反馈结果，返回值类型应为 void；若无需外部输入，形参列表应写为 void。
函数在 main 函数之后定义时，须在 main 之前提供原型声明，以便编译器校验参数与返回值类型。

C 语言参数传递严格遵循“值传递”原则。调用函数时，系统计算实参的值并复制给形参局部变量。
形参的生命周期仅在函数调用期间有效，在函数内部对形参的重新赋值绝不会改变实参原本的值。
return 语句负责结束当前函数执行并返回结果，其类型需与声明一致；void 函数可通过不带值的
return; 语句提前终止执行。

### 例题
工件分拣站需要一个判断工件重量是否合格的函数。工件重量（单位：克）在合格区间
[min_g, max_g] 内返回 1，否则返回 0。编写该函数并进行调用演示。

```c
#include <stdio.h>

int is_weight_qualified(int weight_g, int min_g, int max_g) {
    if (weight_g >= min_g && weight_g <= max_g) {
        return 1;
    }
    return 0;
}

int main(void) {
    int pass_a = is_weight_qualified(105, 90, 110);
    int pass_b = is_weight_qualified(85, 90, 110);
    printf("工件 A: %d, 工件 B: %d\n", pass_a, pass_b);
    return 0;
}
```
程序输出：工件 A: 1, 工件 B: 0。
解答说明：is_weight_qualified 接收三个整型实参并按值传递给形参，经条件判定后返回 1 或 0，
main 函数成功接收返回值并完成打印。

### 常见错误
1. 误以为修改形参能改变实参：在函数内给形参赋值，误以为主函数中的实参也会同步改变。
2. 有返回值的函数遗漏 return：声明为 int 返回类型但部分分支无 return，导致返回垃圾值。
3. 缺失前置函数声明：函数定义在 main 之后却未在前部声明原型，引发编译告警或报错。

## 作用域、生命周期与 static

作用域决定变量名的可见范围。在花括号 `{}` 内定义的变量具有块作用域，属于局部变量，
仅在其代码块内有效；在所有函数外定义的变量具有文件作用域，属于全局变量，其作用域
自定义处持续至文件末尾。不同代码块内可以定义同名局部变量，它们互相独立、互不干扰。

生命周期指变量占用内存的有效时长。普通局部变量进入代码块时分配，退出时销毁；全局变量
贯穿整个程序生命周期。使用 static 修饰局部变量时，其作用域仍为当前局部块，但生命周期
被延长至程序结束。static 局部变量只初始化一次，后续调用保留上次退出时的最新值，
非常适合记录工件累计分拣量或工位状态计数。

### 例题
分拣工位需要累计流水线上通过的工件总数。编写 record_item 函数，每次调用使 static
局部变量递增并返回当前累计总数。

```c
#include <stdio.h>

int record_item(void) {
    static int total = 0;
    total = total + 1;
    return total;
}

int main(void) {
    printf("第 1 次计数: %d\n", record_item());
    printf("第 2 次计数: %d\n", record_item());
    printf("第 3 次计数: %d\n", record_item());
    return 0;
}
```
程序输出：第 1 次计数: 1，第 2 次计数: 2，第 3 次计数: 3。
解答说明：total 被声明为 static 局部变量，初值赋 0 仅执行一次。每次调用函数时 total 保留
上次结果并自增，从而稳定实现工件过检累计。

### 常见错误
1. 误以为 static 局部变量每次调用都会重置：误以为每次进入函数都会重新赋值为初值。
2. 滥用全局变量：为在函数间共享数据随意定义全局变量，导致工位各功能逻辑紧耦合且易被篡改。
3. 跨块访问局部变量：在花括号外部访问其内部定义的局部变量，导致编译报错未定义标识符。

## 边界输入与断言测试

工业分拣要求高确定性与高可靠性，断言（assert）是验证程序前置条件与逻辑不变量的关键工具。
包含头文件 `<assert.h>` 后可使用 assert 宏：当括号内表达式为真（非 0）时程序正常执行；
当表达式为假（等于 0）时，断言触发失败，终端输出出错文件名与行号并调用 abort() 中止程序。

边界输入测试指在判决条件的临界点设计测试用例。多数软件缺陷往往潜藏在边界阈值处，
例如判定工件尺寸合格时，除了测试常规中间值外，必须重点测试恰好等于合格下限与上限的阈值点，
以及紧邻阈值外侧与内侧的数值。系统化的边界测试能精准拦截 `<` 与 `<=` 符号混淆等离散错误。

### 例题
工件高度传感器检测区间为 10 mm 到 200 mm（含两端点）。编写 is_height_valid 函数，
并编写包含临界边界断言的测试函数进行全面验证。

```c
#include <stdio.h>
#include <assert.h>

int is_height_valid(int height_mm) {
    if (height_mm < 10 || height_mm > 200) {
        return 0;
    }
    return 1;
}

int main(void) {
    assert(is_height_valid(9) == 0);   // 下限外侧
    assert(is_height_valid(10) == 1);  // 恰好等于下限
    assert(is_height_valid(200) == 1); // 恰好等于上限
    assert(is_height_valid(201) == 0); // 上限外侧
    printf("所有边界断言测试全部通过！\n");
    return 0;
}
```
程序输出：所有边界断言测试全部通过！
解答说明：通过针对下限（9、10）与上限（200、201）设计覆盖邻域的 assert 断言，所有判定
均符合预期，成功检验了闭区间边界逻辑的严密性。

### 常见错误
1. 在 assert 内部编写带业务副作用的表达式：如写 assert(feed() == 1)，关闭断言时导致逻辑漏执行。
2. 仅测中间常规值忽略临界边界：仅验证了 100 mm 正常，遗漏 10 mm 与 200 mm 边界点检验。

## 递归入门

递归是函数直接或间接调用自身的编程技巧。递归包含两个核心要素：基准情形（递归出口）
和递归递推步。基准情形无需继续递归，直接返回确定数值；递推步将原问题拆解为规模更小
的同类子问题，每次递归调用必须严格向基准情形推进，直至达到出口后回溯计算。

递归执行时每次调用都会在栈上分配新的栈帧以保存形参和返回地址。在单片机等内存资源
极度受限的嵌入式场景中，递归层数过深或缺少基准出口会导致无限压栈，迅速引发栈溢出，
造成工位控制器死机或复位。因此在单片机上通常优先使用 for 或 while 循环代替简单递归。

### 例题
工位分批次算法需要计算整数 n 的阶乘（n!）。编写递归函数 factorial，并追踪其计算过程。

```c
#include <stdio.h>

int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

int main(void) {
    int result = factorial(4);
    printf("4! 计算结果: %d\n", result);
    return 0;
}
```
程序输出：4! 计算结果: 24。
解答说明：调用 factorial(4) 展开为 4 * factorial(3)，逐层递推至 factorial(1) 触发基准
条件返回 1，随后回溯计算 1 * 2 * 3 * 4 = 24，完成阶乘求解。

### 常见错误
1. 缺失基准情形或递归条件未推进：导致函数陷入无限递归调用，迅速耗尽栈空间引发崩溃。
2. 忽视单片机调用栈深度开销：在 RAM 紧缺的单片机上使用深层递归，引起栈溢出破坏其他变量。

## 单元小结
- 函数是构建工件分拣站逻辑的基础模块，形参与实参通过值传递交互，void 与 return 明确出入契约。
- 局部变量在退出代码块后销毁，static 局部变量可持久保存工位工件计数等历史累计状态。
- 边界测试是工控高可靠性的保障，assert 宏能高效拦截前置违规并严格检验阈值临界行为。
- 递归必须拥有明确的基准出口并确保规模收敛，在资源紧缺的单片机编程中需警惕调用栈开销。
