# 编程与调试

本单元学习如何使用结构化文本（ST）与功能块组织工位控制逻辑，并在仿真环境中开展用例测试与通信联调。

## 本单元知识点
- 结构化文本 ST 入门：掌握 ST 语法、条件分支与梯形图等效逻辑表达。
- 功能块与程序组织：掌握功能块（FB）封装、多实例复用及参数传递机制。
- 仿真与测试用例：掌握输入信号强制技巧与工位正常、异常流程用例验证。
- HMI 与通信：掌握触摸屏状态监控、报警机制及 Modbus 寄存器数据交互。
- 送料检测分流仿真（自评）：在仿真软件中完成三步顺序控制与故障恢复实作。

## 结构化文本 ST 入门
结构化文本（Structured Text, ST）是 IEC 61131-3 标准定义的文本式编程语言，
语法结构类似于 Pascal。在处理复杂数学运算、状态机逻辑和配方参数时，
ST 比梯形图更为紧凑清晰。

变量赋值必须使用专用符号 :=，而单等号 = 仅用于条件判断中的数值或布尔比较。
ST 语言支持的标准布尔运算包括 AND、OR 和 NOT，
比较运算包括 =、<>、<、<=、> 和 >=。

条件分支常用 IF ... THEN ... ELSIF ... ELSE ... END_IF 语句实现互锁或使能；
多工位状态转移则推荐使用 CASE ... OF 语句，通过整型状态字驱动工序步进。
梯形图中的常开触点串联等效于 ST 中的 AND 运算，并联等效于 OR 运算，
常闭触点等效于 NOT 运算，线圈驱动则等效于变量赋值。

### 例题
问题：分拣站到位传感器检测到工件到位（Sens_Arrived 为 TRUE），且相机判定
工件合格（Cam_OK 为 TRUE），需要将合格品推杆电磁阀（Valve_Pass）置为 TRUE；
若急停回路状态 Estop_OK 为 FALSE，则推杆电磁阀必须强制断开。
急停按钮为常闭接线，Estop_OK 正常为 TRUE，按下急停或线路断开时为 FALSE。
请用 ST 语句编写该控制逻辑。

解答：
```pascal
IF NOT Estop_OK THEN
    Valve_Pass := FALSE;
ELSIF Sens_Arrived AND Cam_OK THEN
    Valve_Pass := TRUE;
ELSE
    Valve_Pass := FALSE;
END_IF;
```
逻辑解析：首要判断急停回路，按下或断线时无条件复位输出；正常运行状态下，
当到位与合格信号同时满足时使能电磁阀，其余工况均关闭推杆。

### 常见错误
- 将赋值符号 := 误写为比较符号 =，导致逻辑赋值失效或编译器报错。
- 遗漏语句结尾的分号 ;，或在 IF、CASE 语句末尾遗漏 END_IF、END_CASE。
- 在状态分支中未能完全闭环处理 ELSE 分支，导致输出变量保持上一周期的旧值。

## 功能块与程序组织
功能块（Function Block, FB）是 IEC 61131-3 中用于封装可复用设备逻辑的核心单元。
与无状态的纯函数（FC）不同，功能块在实例化时会分配专属的背景数据块，
用于在不同扫描周期之间持久化保存定时器、计数器及内部标志位。

功能块通过 VAR_INPUT 声明外部输入参数，通过 VAR_OUTPUT 声明外部输出参数，
通过 VAR_IN_OUT 声明双向引用变量，通过 VAR 声明私有内部静态变量。
私有变量由该实例独占，外部程序不能随意破坏其内部封装。

在桌面分拣站中，合格品挡板和不合格品挡板具有完全相同的电磁阀伸缩、到位检测
与动作超时报警逻辑。通过编写通用的气缸控制功能块 FB_Cylinder，
再分别为两个气缸声明独立实例，可极大提升程序的可维护性并消除重复代码。

### 例题
问题：编写一个气缸动作监控功能块 FB_Cylinder 的接口声明，包含伸出命令输入、
到位传感器输入、电磁阀输出与动作超时报警输出。

解答：
```pascal
FUNCTION_BLOCK FB_Cylinder
VAR_INPUT
    bExtendCmd : BOOL;   (* 伸出命令 *)
    bSensorExt : BOOL;   (* 伸出到位传感器 *)
END_VAR
VAR_OUTPUT
    bValveOut  : BOOL;   (* 电磁阀输出 *)
    bTimeout   : BOOL;   (* 动作超时报警 *)
END_VAR
VAR
    TimerExt   : TON;    (* 内部动作计时器 *)
END_VAR
```
逻辑解析：输入输出通过标准接口与外部硬件解耦，内部包含私有的 TON 定时器实例，
保证多套机构调用时内部计时互不干扰。

### 常见错误
- 多个物理执行机构（如两个不同气缸）调用同一个 FB 实例，导致内部定时器相互覆盖。
- 将需要跨周期记忆的状态变量定义为临时局部变量（VAR_TEMP），周期结束数据丢失。

## 仿真与测试用例
PLC 仿真（Simulation）是在个人电脑上运行软 PLC 运行时，模拟控制器 CPU、
扫描周期以及输入输出映像区。在缺乏物理工件和机械台架时，仿真可验证逻辑闭环。

强制输入（Force Input）是仿真测试的核心手段。开发者可手动将输入映像区
（如工件到位开关 I0.0）锁定为 1 或 0，模拟工件到达或离开，检验状态转移。

测试用例（Test Case）必须同时覆盖正常流程与故障流程。
正常流程验证：送料到达、相机检测判定、挡板动作分流及计数器自增。
故障流程验证：传感器超时未到位、相机未返回检测结果、分流执行中急停。
规范测试应记录前置条件、测试输入序列、预期输出及实测结果。

### 例题
问题：为分拣站设计一个“送料超时故障”测试用例，送料电机启动后若在 3.0 秒内
传感器未感应到工件，系统应报警停机。请写出用例要素。

解答：
前置条件：系统处于“自动待机”状态，故障报警灯熄灭，电机停止。
输入操作：触发“启动”按钮信号置 1；电机启动后，持续保持到位传感器输入为 0。
预期结果：
1. 计时达到 3.0 秒时，送料电机输出立即断开；
2. 故障报警输出置 1，状态机转入“故障停机”；
3. 后续再次按启动按钮无效，必须经过人工复位方可回到待机。

### 常见错误
- 测试完成后忘记取消强制变量（Unforce），导致后续自动化运行被固定数值阻塞。
- 混淆“修改变量当前值”与“强制输入”：普通修改会在下一周期的输入刷新中被立刻覆写。
- 只测试单次正常工序，忽略了连续批量工件流转时的状态机复位与标志位清理。

## HMI 与通信
人机界面（HMI）用于实时显示设备运行工况、当前产量、传感器状态，并提供参数
设定与手动调试按钮。报警画面则用于集中呈现故障发生时间、报警原因与复位引导。

Modbus 是工业控制中最通用的开放式通信协议。标准数据模型包含四类对象：
离散输入（1xxxx，只读开关量）、线圈（0xxxx，读写开关量）、
输入寄存器（3xxxx，只读 16 位字）、保持寄存器（4xxxx，读写 16 位字）。

上位机（PC 或测试脚本）通过 Modbus 周期性读取保持寄存器中的合格品数、
不合格品数和当前工位状态字，并存入本地 CSV 文件供质量追溯。
建立通信时应严格定义点位表，统一寄存器地址基准（0 基寻址与 1 基寻址）。

### 例题
问题：上位机需要通过 Modbus 读取分拣站生产数据，定义合格品计数存放于保持寄存器
40001，废品计数存放于 40002。若协议层使用 0 基地址查询，读取这两个计数值的
功能码与起始地址分别是什么？

解答：
功能码：03（Read Holding Registers，读取保持寄存器）。
起始地址：0000H（十六进制 0，对应保持寄存器 40001 的偏移量）。
读取寄存器数量：2。
解析：Modbus 规范中功能码 03 用于读保持寄存器；寄存器 40001 在报文通信层
采用相对偏移地址，即 40001 - 40001 = 0。

### 常见错误
- 混淆线圈（按位操作）与寄存器（按 16 位字操作），尝试用线圈读取整型计数值。
- 忽视通信地址的偏移基准（1 基与 0 基之差），导致上位机读取到的数据整体偏移一个通道。
- 将安全回路（如急停停机）完全依赖网络通信传输，违背硬接线安全联锁规范。

## 送料检测分流仿真（自评）
目标：在 PLC 仿真环境中构建并验证桌面分拣站顺序控制逻辑，实现正常分拣与三种
异常故障的安全联锁停机与人工复位。

材料或准备：安装支持 IEC 61131-3 的 PLC 仿真软件；准备好 I/O 变量分配表及内部状态机变量。

步骤：
1. 建立状态机：编写送料（Feed）、检测（Inspect）、分流（Sort）三步顺序控制逻辑。
2. 仿真正常流程：分别模拟合格工件与不合格工件的完整流程，验证挡板动作与料盒分流。
3. 测试传感器超时：启动送料后保持到位传感器为 0，验证 3.0 秒后系统触发超时停机报警，
   且传感器恢复后报警仍保持，必须人工复位后才回到待机。
4. 测试检测结果缺失：工件到位后不输入相机判定信号，验证分流不动作、检测超时停机及报警指示，
   并验证人工复位前设备不重新运行。
5. 注入急停与人工复位：在分流动作执行中触发急停信号，确认设备立即停机；
解除急停后必须按下人工复位按钮，设备才能回到待机状态。

### 自评清单
- [ ] 能在仿真器中正常走完合格品推入正品盒、不合格品推入次品盒的完整流程。
- [ ] 当工件到位传感器未在设定时限（3.0 秒）内动作时，仿真系统能置位并保持报警标志、停机，人工复位前不重新运行。
- [ ] 当相机未给出检测判定结果时，分拣推杆保持互锁不误动作，并在超时后停机报障。
- [ ] 触发急停后所有输出立即断开，解除急停后设备不自启，经人工复位后方可重新启动。

说明：完成上述全部操作且自评清单所有检查项均达标后，请在“学习路径”中把该知识点标记为“已会”。

## 单元小结
- ST 语言通过结构化分支与表达式提升了复杂逻辑的紧凑性，与梯形图具备等价逻辑表达能力。
- 功能块（FB）借助独立的背景数据块实现逻辑封装与多实例复用，是模块化程序架构的基础。
- 仿真测试通过强制输入与故障注入，可前置验证工位顺序、超时逻辑与急停闭环。
- HMI 与 Modbus 通信实现了设备状态监视、报警呈现与生产数据的实时采集汇总。
