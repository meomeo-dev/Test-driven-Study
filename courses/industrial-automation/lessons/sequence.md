# 顺序控制

本单元围绕桌面质检分拣站的动作节拍，讲解工业顺序控制的设计方法与工程规范，
涵盖 IEC 61131-3 顺序功能图（SFC）、结构化文本状态字架构及电气与工艺联锁。

## 本单元知识点
- 顺序功能图 SFC：掌握步、转换条件与动作要素，理清单序列、选择分支与并行分支。
- 用状态字实现顺序控制：基于整数状态变量与 CASE 语句实现单步步进与受控流转。
- 互锁与联锁：建立正反转电气互锁机制，实现机构动作先后联锁与工艺先决校验。

## 顺序功能图 SFC
顺序功能图（SFC）是 IEC 61131-3 标准中专门用于组织与描述离散制造系统顺序行为
的图形化编程规范。SFC 的三大核心构成要素包括：步（Step）、转换条件（Transition）
以及步内动作（Action）。
步代表系统所处的稳定控制阶段，包含初始步、活动步与不活动步。在任意时刻，
只有当某一步处于活动状态，且其后续紧邻的转换条件计算结果为真时，步的转换才会
发生。转换一旦触发，前级步立即变为不活动状态，其关联的非保持动作停止执行，
后续步同时被激活并执行相应工步动作。

SFC 遵循严格的拓扑语法规则：两个步之间必须且只能包含一个转换条件；两个转换
条件之间必须且只能包含一个步。绝对不允许步与步直接相连，也不允许转换条件之间
直接相连。在结构组织上，SFC 主要包含三种典型序列拓扑：
1. 单序列：步与转换条件严格单线交替串联，工艺路径唯一且固定。
2. 选择分支与汇合：在单水平实线下方引出多个独立的转换条件，系统根据互斥条件
仅选择其中一条分支执行，最后在单水平线处汇合。分支条件必须互斥以防多路竞争。
3. 并行分支与汇合：在前级转换条件成立后，通过双水平实线同时激活多个后续步；
各并行分支同步独立运行，汇合处同样采用双水平实线，必须等待所有分支的最终步
全部处于活动状态且后续总转换条件满足时，才同步退出并转入下一阶段。

在桌面质检分拣站中，工件进料与气缸夹紧后，系统通过选择分支判断相机检测结果：
判定合格则转入合格品推料步，判定不合格则转入次品推料步，随后汇合进入复位步。

### 例题
在桌面分拣工位中，工件夹紧后需要同时启动“相机图像采集计算”与“打标预热”，
两项任务均完成后方可驱动气缸松开并执行分流。请说明该工艺在 SFC 中属于何种分支
结构，并写出从分支激活到汇合完成的动作时序。

解答：
1. 结构判定：该工艺属于典型的 SFC 并行分支与汇合结构，图符上采用双水平实线。
2. 动作时序分析：
- 激活过程：当前级“夹紧到位”转换条件满足时，双水平线同时激活“图像采集步”
与“打标预热步”，两项动作在不同分支中并发独立执行。
- 汇合过程：由于视觉处理与打标预热耗时可能不同，先完成的分支将在汇合前的
最终步保持等待。
- 退出过程：当两个分支的步均变为活动步，且双水平线下方总转换条件“采集完成
AND 预热完成”为真时，两个分支同时退出，后续“松开与分流步”被同步激活。
3. 结论：并行分支通过双横线同步机制，严格保证了多机构并发动作的时序一致性。

### 常见错误
- 混淆选择分支与并行分支图符：将选择分支画为双横线，导致互斥路径被错误地同时
并发执行；或将并行分支误画为单横线，破坏多任务同步机制。
- 选择分支条件未设计为严格互斥：在同一选择节点下，多个分支的条件可能同时为真，
导致系统产生非预期的并发转移或分支竞争冲突。
- 遗漏转换条件：在相邻两个步之间直接使用连接线相连，违反了 IEC 61131-3 步与
条件必须交替出现的底层编译规则。

## 用状态字实现顺序控制
在工业 PLC 编程中，除图形化 SFC 外，更为通用且便于移植的文本实现方法是使用
状态机架构。状态机通常通过一个整数变量（如 state 或 step）作为“状态字”，配合
结构化文本（ST）中的 CASE 语句集中管理整个工位的工序流转。这种设计将离散工步
与底层扫描解耦，结构清晰且易于维护。

实现高可靠性状态机需遵循“每步只做一件事，转换条件清楚”的黄金设计原则：
1. 离散工步分配：推荐以 10 为步长进行状态编号（例如 0 为待机空闲，10 为上料，
20 为检测，30 为分选，99 为故障保护）。预留的数字编号便于后续工艺升级时插入
微调或缓冲工步，而无需整体改写原有逻辑。
2. 单步动作聚焦：每个状态分支内部仅驱动当前工步所需的执行机构或使能标志。
对于非保持动作，应在对应状态中连续赋予确定值，状态退出时予以复位。
3. 转移条件闭环：状态跃迁必须由外部传感器物理信号或逻辑完成标志明确触发，
形式为：IF 转移条件 THEN state := 下一状态; END_IF;。严禁无条件跳变。
4. 防御性缺省处理：CASE 结构中必须包含 ELSE 分支。当状态变量因内存干扰或
逻辑异常变为非预期数值时，系统能立即捕获并强制转入安全停机或复位状态。

### 例题
编写桌面质检分拣站“上料夹紧”至“触发相机”两个工步的结构化文本（ST）代码。
要求：待机状态（state=0）收到启动信号 Start 且料仓传感器 Sensor_In 为真时进入
夹紧步（state=10）；夹紧气缸到位传感器 Sensor_Clamp 为真时进入拍照步（state=20）；
相机完成信号 Test_Done 为真时进入分拣步（state=30）。

解答：
结构化文本实现代码如下：
```pascal
CASE state OF
    0: (* 待机空闲 *)
        Cylinder_Clamp := FALSE;
        Camera_Trig := FALSE;
        IF Start AND Sensor_In THEN
            state := 10;
        END_IF;
    10: (* 夹紧工件 *)
        Cylinder_Clamp := TRUE;
        Camera_Trig := FALSE;
        IF Sensor_Clamp THEN
            state := 20;
        END_IF;
    20: (* 触发相机检测 *)
        Cylinder_Clamp := TRUE;
        Camera_Trig := TRUE;
        IF Test_Done THEN
            Camera_Trig := FALSE;
            state := 30;
        END_IF;
    ELSE
        Cylinder_Clamp := FALSE;
        Camera_Trig := FALSE;
        state := 0;
END_CASE;
```
逻辑分析：
在 state=10 时只负责驱动夹紧气缸，必须等待物理传感器 Sensor_Clamp 闭合才转移；
在 state=20 保持夹紧并置位拍照触发，检测完成信号 Test_Done 到达后复位触发信号
并转入 state=30。各步动作专一且流转条件完全闭环。

### 常见错误
- 单周期内连续跃迁：在一个 PLC 扫描周期内连续无延时地修改多次状态字，导致中间
工步未能在物理 I/O 上维持有效电平，外部执行机构无法响应。
- 跨状态输出残留：在上一状态置位输出线圈后，退出时未显式清零，导致机构在后续
无关工步中持续通电误动。
- 缺少 ELSE 分支保护：未编写异常状态处理，一旦数值受到干扰发生跑飞，程序将陷入
未定义分支导致生产线失去响应。

## 互锁与联锁
在工业自动化控制系统中，互锁（Interlock）与联锁（Linkage）是保障人身安全、
防止设备机构自毁以及确保工艺顺序合规的两大核心防御机制：
1. 互锁（互斥闭锁）：用于防止两个或多个在物理上绝对互斥、若同时触发将造成短路
或机械破坏的动作同时发生。最典型的场景是电动机正反转控制，以及双作用气缸的
伸出与缩回动作。若正反转交流接触器同时吸合，将造成电源相间金属性短路。互锁
遵循双重互锁原则：既要在 PLC 软件中将对方常闭触点串入控制线圈，又必须在硬件
配电回路中串入对方接触器的辅助常闭触点，硬件互锁绝不可省。
2. 联锁（条件依赖联锁）：用于规范执行机构之间的工艺先后依赖关系，即“动作 B
的执行必须以条件 A 的达成并持续成立为前提”。在分拣站中包括：
- 挡板与送料联锁：送料气缸处于缩回安全位且到位传感器闭合前，严禁分选挡板摆动，
防止两套机械臂发生空间干涉相撞。
- 检测结果确认前不分流：分选机构动作回路必须串入视觉检测有效标志位。若相机检测
超时、通信断开或未给出结论，联锁逻辑必须封锁分拣挡板，杜绝未检工件混入。

工程应用中，联锁信号必须取自现场物理传感器（如接近开关、磁性开关的常开触点），
不得单纯依赖虚拟计时器或中间标志；一旦联锁失效，系统必须紧急联锁停机。

### 例题
桌面分拣站的分流机构由正转（拨向合格品箱，输出 Q0.1）与反转（拨向次品箱，
输出 Q0.2）电机驱动。工艺要求：只有当送料气缸缩回传感器 I0.3 闭合，且视觉判定
完成标志 Test_OK_Valid 有效时，才允许电机运转。请文字描述梯形图控制逻辑。

解答：
梯形图文本描述如下：
- 正转控制回路（Q0.1）：常开触点 Test_OK_Valid 串联常开触点 I0.3（气缸安全位），
再串联合格分拣触发指令触点，再串联反转输出 Q0.2 的常闭触点（软件互锁），
最后驱动正转输出线圈 Q0.1。
- 反转控制回路（Q0.2）：常开触点 Test_OK_Valid 串联常开触点 I0.3（气缸安全位），
再串联次品分拣触发指令触点，再串联正转输出 Q0.1 的常闭触点（软件互锁），
最后驱动反转输出线圈 Q0.2。
- 逻辑说明：I0.3 与 Test_OK_Valid 构成了工艺先决联锁，杜绝了机械撞击与误分流；
Q0.1 与 Q0.2 的常闭触点交叉互锁，杜绝了正反转同时吸合的电气故障。

### 常见错误
- 仅用软件互锁替代电气硬件互锁：当 PLC 继电器触点熔焊或输出晶体管击穿时，
软件互锁失效，导致主回路相间直接短路跳闸。
- 联锁信号缺失物理校验：仅凭时间延时猜测气缸已退回，若气缸气压不足发生机械
卡阻，分拣挡板强行伸出将造成机构断裂损坏。
- 结果异常时强行默认分流：在视觉通信超时或丢失数据包时，未设置联锁拦截，
导致大量未经判定工件直接流入合格品成品箱。

## 单元小结
- 顺序功能图 SFC 以步、转换条件与动作为核心，通过单序列、选择分支与并行分支
清晰规范复杂的工位动作逻辑。
- 状态字配合 CASE 语句是工业顺序控制的标准文本模式，严格遵循单步单职责与
闭环转移原则，并配置防御性缺省分支。
- 互锁用于消除物理互斥冲突，必须采用软件与电气硬件双重互锁保障绝对安全。
- 联锁用于约束动作先后依序关系，确保送料避让及检测结果有效确认前严禁动作。
