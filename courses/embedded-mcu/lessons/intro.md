# 单片机与开发环境

本单元带领初学者建立嵌入式硬件认知，掌握工具链烧录与超级循环架构，
并掌握引脚电气安全底线，为桌面质检分拣站的软硬件联调奠定坚实基础。

## 本单元知识点

- 单片机的组成：认识 CPU、Flash、RAM 与外设，理解单片机与电脑的体系差异。
- 开发环境、编译与下载：掌握交叉编译、固件烧录、串口监视器与模拟器验证。
- 程序结构 setup 与 loop：掌握上电单次初始化与无限循环轮询的超级循环。
- 逻辑电平与引脚电气限制：理解 3.3V 与 5V 电平阈值、引脚电流限额与接口防护。

## 单片机的组成

单片微型计算机（Microcontroller Unit，MCU，简称单片机）是将中央处理器
CPU、闪存 Flash、随机存取内存 RAM、通用输入输出引脚 GPIO、定时器以及
通信接口等关键部件集成在单一硅片上的微型计算机系统。在桌面质检分拣站中，
单片机负责协调到位开关、分拣舵机与上位机通信。

单片机内部的核心功能单元各有明确分工：
1. CPU（中央处理器）：系统的控制中枢，负责从存储器中抓取指令并解码执行。
2. Flash（闪存）：非易失性存储器，断电后内容不丢失，用于存放编译后的
   程序固件镜像。
3. RAM（随机存取存储器）：易失性存储器，读写速度极快，断电后数据全部清零，
   用于保存程序运行期间的全局变量、局部变量、中间计算结果与函数调用栈。
4. GPIO 与外设接口：实现芯片与现实世界的电信号交互，采集传感器输入或控制
   外部执行机构。
5. 时钟系统：为芯片内部所有数字逻辑提供精确的时间节拍，驱动各模块协调同步。

单片机与普通个人电脑（PC）在设计目标上存在本质区别。PC 面向通用计算场景，
依赖高主频多核 CPU、吉字节（GB）级内存与大型操作系统（如 Windows/Linux），
追求多任务吞吐与高浮点算力。而单片机面向专用控制任务，系统资源紧凑（千字节
KB 至兆字节 MB 级），无庞大操作系统开销，具有成本极低、微秒级实时响应、
功耗极小以及能够直接精确操控引脚物理电平的优势。在桌面分拣站中，PC 负责运行
高算力图像质检算法，单片机则专注高实时性的工件到位捕捉与挡板动作控制。

### 例题

题目：在桌面质检分拣站控制系统中，控制程序固件代码、实时统计的良品工件计数
变量分别存放在单片机的什么存储区域？若车间供电突然中断并重新通电，这两个数据
分别会发生什么变化？

解答：
1. 固件代码存放于单片机内部的 Flash 存储器中；实时统计的工件计数值存放于
   RAM 存储器中。
2. 当供电中断并重新上电后，Flash 中的固件代码完好无损，单片机会重新加载并
   从头开始执行程序；而 RAM 具有易失性，断电导致其中保存的变量数据全部丢失，
   工件计数值在重新启动后被重新初始化为零。

### 常见错误

1. 混淆 Flash 与 RAM 的存储特性：误以为在代码中定义的全局变量在断电后仍能
   长久保存，或者误以为每次对普通变量赋值都会消耗 Flash 的擦写寿命。
2. 算力边界定位不清：试图在轻量级单片机上直接加载深度学习大模型处理高分辨率
   工件图像，脱离了嵌入式微控制器的实际资源定位。

## 开发环境、编译与下载

嵌入式软件开发通常在个人电脑（宿主机 Host）上进行，并通过专用软件套件完成
从源代码到目标单片机（目标机 Target）可执行程序的转换。常用的开发环境包括
Arduino IDE、配置了 ESP-IDF 插件的 VS Code，或基于浏览器的 Wokwi 模拟器。

开发与交付的核心流程包含三个基本环节：
1. 交叉编译（Cross Compilation）：由于单片机内部不具备运行编译器的资源，
   PC 端的编译器（如 avr-gcc、xtensa-esp32-elf-gcc）将人类编写的 C/C++
   文本代码编译、汇编、链接为目标 MCU 架构专用的二进制固件镜像（.bin/.hex）。
2. 固件烧录（Upload/Flashing）：通过 USB 转串口芯片或硬件调试器（如 DAP-Link），
   利用引导加载程序（Bootloader）协议将编译好的机器码写入单片机内部 Flash。
3. 串口监视器（Serial Monitor）：单片机将运行时状态通过 UART 串口转化为
   文本字符流上传给电脑，开发者在串口监视窗口中实时观察调试日志，完成分拣逻辑
   的闭环测试。

在尚未取得实体硬件时，单片机模拟器是验证逻辑的重要工具。模拟器能够在软件层面
仿真 MCU 的指令执行、GPIO 电平翻转及串口通信，提升前期开发效率；它不能完全
复现真实电气特性与时序，上板后仍需实测。

### 例题

题目：开发者在 IDE 中修改了桌面分拣站的串口输出提示语，随后直接打开串口
监视器观察，发现电脑接收到的仍然是修改前的旧提示语。请从工具链流程角度分析
造成这一现象的原因，并给出正确的操作步骤。

解答：
原因分析：修改源代码后，若没有执行“编译并上传（Upload）”操作，电脑仅保存了
磁盘上的文本文件，新代码既未编译为机器指令，也未写入单片机的 Flash 中，
单片机内部运行的依然是上次烧录的旧版本固件。
正确步骤：关闭串口监视器以释放串口占用，点击 IDE 中的“上传”按钮触发自动化
编译与固件烧录流程；等待提示烧录成功后，再次打开串口监视器观察最新输出。

### 常见错误

1. 误将“验证/编译”当成“上传/下载”：仅点击编译按钮确认语法无误，未真正将镜像
   写入硬件 Flash，误以为硬件已在运行最新代码。
2. 串口端口（COM）被独占或波特率不匹配：多个调试工具同时抢占同一串口造成
   烧录失败，或监视器波特率与程序中设置的值不一致导致输出严重乱码。

## 程序结构 setup 与 loop

单片机裸机固件通常采用“前后台超级循环”（Superloop）程序架构。在以 Arduino
为代表的嵌入式开发框架中，这一架构被高度抽象为 setup() 和 loop() 两个核心
函数，它们构成了整个系统的生命周期主干。

核心函数的职责与运行机制如下：
1. setup() 函数：系统上电或硬件复位后仅执行一次。主要用于完成系统底层硬件与
   外设的初始配置，例如调用 pinMode 设置引脚输入输出属性、调用 Serial.begin
   初始化串口波特率、以及驱动分拣舵机回到初始归位角度。
2. loop() 函数：在 setup() 成功执行完毕后被系统置于死循环中反复调用。系统在
   每个循环周期内依次轮询到位传感器、解析上位机指令、执行分拣策略并刷新输出。

超级循环架构要求代码具备高流转性。如果在 loop() 中使用了较长时长的阻塞式延时
函数（如 delay(3000)），CPU 将在此期间持续空转，无法响应任何外部引脚状态的
变化，极易造成分拣工位传感器信号漏检或通信数据接收超时丢包。

### 例题

题目：分析下方用于桌面分拣工位指示灯控制的超级循环代码，说明系统从上电开始，
板载 LED 引脚（LED_PIN）的电平变化时序与串口输出行为：
```c
const int LED_PIN = 13;
void setup() {
  Serial.begin(9600);
  pinMode(LED_PIN, OUTPUT);
  Serial.println("System Started");
}
void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(500);
  digitalWrite(LED_PIN, LOW);
  delay(500);
}
```

解答：
1. 上电或复位瞬间，系统首先执行 setup()：初始化串口波特率为 9600 bps，将
   13 号引脚配置为数字推挽输出模式，并通过串口单次打印一行 "System Started"。
2. setup() 执行完毕后进入 loop() 循环：LED 引脚首先被拉高为 HIGH 保持 500 毫秒，
   接着被拉低为 LOW 保持 500 毫秒；当本次 loop() 执行到末尾后，系统立即重新
   进入 loop() 开始下一次执行。因此，LED 灯将以 1 秒为周期（高 0.5 秒、低 0.5 秒）
   持续匀速闪烁，而串口不会再打印启动提示。

### 常见错误

1. 将周期性任务错误写在 setup() 中：误将工件到位检测逻辑放置在 setup() 里，
   导致单片机仅在开机瞬间检测一次工件，后续送达的所有工件均无法被感知。
2. 在 loop() 中滥用大延时：在处理舵机动作时直接调用 delay(2000) 进行阻塞等待，
   导致流水线下一个快速通过的工件完全漏检。

## 逻辑电平与引脚电气限制

单片机通过通用输入输出（GPIO）引脚与外部世界进行物理电气交互。在处理分拣站的
传感器与舵机信号时，必须严格遵守数字逻辑电平规范与引脚电气极限，防止器件损坏。

核心电气规则与参数边界包括：
1. 逻辑电平标准：嵌入式系统中常见的数字逻辑标准为 5V 逻辑（如经典 AVR）与
   3.3V 逻辑（如 ESP32，其引脚不耐 5V）。数字引脚通过预设阈值区分高低电平：
   - 高电平输入门限（VIH）：引脚识别为逻辑 1 所需的最低输入电压。
   - 低电平输入门限（VIL）：引脚识别为逻辑 0 所允许的最高输入电压。
   输入电压处于 VIL 与 VIH 之间时属于不确定逻辑态，应坚决避免。
2. 超压保护红线：对于供电电压为 3.3V 且非 5V 耐受（5V Tolerant）的单片机，
   其输入引脚绝对不可直接接入 5V 传感器信号。超出 VDD+0.3V 的电压会使
   芯片内部的 ESD 保护二极管导通，可能造成引脚永久损坏。5V 信号接入前必须经由电阻分压
   网络或专用双向电平转换模块降压至 3.3V。
3. 引脚电流负荷限制：单片机 GPIO 引脚的输出驱动能力极弱，单个引脚的最大拉电流
   （Source）与灌电流（Sink）通常在 10 mA 至 40 mA 之间。单片机引脚仅能用于
   传递控制信号（如舵机 PWM 控制线），严禁直接连接电机绕组或舵机动力电源线，
   大电流负载必须配备外接独立电源驱动。

### 例题

题目：桌面分拣站使用 3.3V 供电的单片机。现有一款工业接近开关，触发时输出 5V
高电平，未触发时输出 0V 低电平。设计者拟使用两个精密电阻 R1 和 R2 组成串联分压
电路将 5V 信号降至安全电平后送入单片机引脚。若 R1（接 5V 信号端）阻值为 2 kΩ，
要求分压后输入引脚的电压为 3.0V，请计算分压电阻 R2（接地端）的阻值应为多少？

解答：
串联电阻分压公式为：Vout = Vin × R2 / (R1 + R2)
代入已知参数：3.0 = 5.0 × R2 / (2000 + R2)
两边同乘 (2000 + R2) 整理得：3.0 × (2000 + R2) = 5.0 × R2
展开计算：6000 + 3.0 × R2 = 5.0 × R2
移项得：2.0 × R2 = 6000，解得 R2 = 3000 Ω（即 3 kΩ）。
选取 3 kΩ 电阻作为 R2，分压后输出刚好为 3.0V，低于 3.3V 额定上限，可安全使用。

### 常见错误

1. 悬空输入（Floating Input）引发电平乱跳：将引脚配置为数字输入模式时，
   若外部没有接上拉或下拉电阻而直接悬空，外界电磁噪声会使读数在 0 和 1 间随机乱跳。
2. GPIO 直驱感性或大电流负载：误将微型舵机或微型继电器的电源正极直接接到 GPIO
   引脚供电，导致引脚严重过流烧毁芯片。

## 单元小结

- 单片机将 CPU、Flash、RAM、时钟与外设高度集成，以高实时、低成本和底层控制见长。
- 交叉编译器在电脑端生成目标固件，通过下载器烧入 Flash，串口监视器是首要调试窗口。
- setup() 专司单次硬件初始化，loop() 负责死循环轮询处理，设计中应尽量避免长延时阻塞。
- 严格遵循 3.3V 与 5V 电平阈值，3.3V 非耐受引脚严禁超压输入，强电动力负载必须外接独立供电。
