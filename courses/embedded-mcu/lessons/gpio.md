# GPIO 输入与输出

本单元学习通用数字输入输出（GPIO）引脚的工作原理与软件编程方法，
掌握 LED 指示灯输出驱动、按键与传感器输入配置、软件消抖及边沿事件检测技术，
为桌面质检分拣站的执行器动作控制与状态采集奠定基础。

## 本单元知识点
- 数字输出驱动 LED：掌握引脚输出配置、高低电平控制、限流电阻计算与拉/灌电流。
- 数字输入与上拉、下拉：掌握输入模式、悬空高阻态危害、内部上拉与低电平有效接法。
- 按键消抖：理解机械触点抖动原理与时间范围，掌握延时与连续采样软件消抖。
- 边沿检测与事件计数：掌握状态比对法识别上升沿与下降沿，实现单次事件精确触发。

## 数字输出驱动 LED
通用输入输出（GPIO）引脚配置为数字输出模式时，可通过程序控制其输出固定的
逻辑电平。使用 pinMode(pin, OUTPUT) 将引脚设置为输出模式后，调用
digitalWrite(pin, HIGH) 引脚输出高电平（通常为 5 V 或 3.3 V），调用
digitalWrite(pin, LOW) 则输出低电平（0 V）。

发光二极管（LED）具有单向导电性与固定的正向导通压降 VF（一般为 1.8 V 至
2.2 V）。由于二极管导通后内阻极小，若直接跨接在引脚与地之间，电流将迅速超过
单片机引脚或 LED 的电气耐受极限而烧毁器件，因此回路中必须串联限流电阻 R。
根据基尔霍夫电压定律与欧姆定律，限流电阻阻值计算公式为：
R = (VCC - VF) / IF
其中 IF 为 LED 的期望工作电流，普通指示灯通常设计在 5 mA 至 15 mA 之间。

单片机驱动 LED 存在两种典型电气拓扑：
1. 拉电流（Source Current）：LED 阳极接 GPIO 引脚，阴极经限流电阻接地。
   引脚输出 HIGH 时点亮，电流自引脚内部电源流出经外部负载入地。
2. 灌电流（Sink Current）：LED 阳极接电源正极 VCC，阴极经限流电阻接 GPIO。
   引脚输出 LOW 时形成回路并点亮，电流自外部电源流入引脚并经内部地线流出。
单片机单个引脚的最大拉/灌电流通常限制在 20 mA 左右，设计时须严格核算。

### 例题
桌面分拣站采用 5 V 单片机驱动一颗合格品绿色指示灯（拉电流接法）。
已知绿色 LED 正向导通压降 VF = 2.0 V，要求工作电流 IF = 10 mA。
请计算所需限流电阻阻值，并编写 setup 中完成引脚 8 初始化与常亮的示例代码。

解答：
限流电阻两端的电压降 VR = VCC - VF = 5.0 V - 2.0 V = 3.0 V。
依据欧姆定律，限流电阻阻值 R = VR / IF = 3.0 V / 0.01 A = 300 Ω。
（实际工程中可选用标称阻值 300 Ω 或 330 Ω 的贴片/色环电阻）。
控制引脚 8 输出高电平的核心程序如下：
```c
void setup() {
  pinMode(8, OUTPUT);      // 配置引脚 8 为数字输出
  digitalWrite(8, HIGH);   // 拉电流接法：输出高电平点亮 LED
}
void loop() {
  // 主循环保持常亮
}
```

### 常见错误
1. 未串联限流电阻直接将 LED 接在 GPIO 引脚上，导致瞬态过流烧毁引脚输出级。
2. 混淆灌电流接法的控制逻辑，在灌电流电路中误向引脚写入 HIGH 导致 LED 熄灭。
3. 多个 LED 同时点亮时仅核算单引脚电流，忽略了芯片 VCC/GND 引脚的总电流上限。

## 数字输入与上拉、下拉
将 GPIO 引脚配置为数字输入模式 pinMode(pin, INPUT) 时，引脚内部呈现
极高的输入阻抗，从外部信号源吸收的漏电流极小（通常在微安级别以下）。

若输入引脚既未接电源高电平也未接地线，该引脚即处于悬空（Floating）状态。
悬空引脚极易受电磁噪声与静电感应影响，输入电压在逻辑阈值间随机漂移，
导致 digitalRead(pin) 读出无规律跳变的 0 或 1，引发系统逻辑误动。

为了提供确定稳定的默认逻辑电平，必须配置上拉电阻（拉向 VCC）或下拉电阻
（拉向 GND）。现代单片机内部通常集成了弱上拉电阻（阻值通常为 20 kΩ 至 50 kΩ），
可通过 pinMode(pin, INPUT_PULLUP) 简便启用。

在工控与嵌入式实务中，推荐采用“低电平有效”（Active Low）的输入连接方式：
按键或到位开关直接串接在 GPIO 引脚与 GND 之间，引脚启用内部上拉电阻。
开关断开时，上拉电阻将引脚钳位在 HIGH；开关按下闭合时，引脚直通地线变为 LOW。
该方案省去外部电阻器件，且外引线路不携带电源正极，大幅降低了意外短路风险。

### 例题
分拣工位的料盒满载检测开关连接在引脚 4 与 GND 之间。
请写出该引脚的模式初始化语句，并编写逻辑：当开关闭合时点亮板载 LED（引脚 13），
开关断开时熄灭该指示灯。

解答：
开关一端接地，引脚必须配置为 INPUT_PULLUP 启用内部弱上拉，形成低电平有效输入。
核心代码如下：
```c
void setup() {
  pinMode(4, INPUT_PULLUP); // 启用内部上拉，常态为 HIGH
  pinMode(13, OUTPUT);      // 指示灯引脚设为输出
}
void loop() {
  int state = digitalRead(4);
  if (state == LOW) {
    digitalWrite(13, HIGH); // 开关闭合输入低电平，点亮指示灯
  } else {
    digitalWrite(13, LOW);  // 开关断开维持高电平，熄灭指示灯
  }
}
```

### 常见错误
1. 按键接在引脚与地之间，但模式误设为 INPUT，导致松开按键时引脚悬空剧烈抖动。
2. 误以为低电平有效接法在按下时读入 HIGH，导致软件判断条件与硬件电平反相。

## 按键消抖
机械轻触按键、微动限位开关内部由弹性金属簧片构成。在机械闭合与断开瞬间，
触点受机械回弹物理特性的影响，会在短时间内发生多次接触与微小弹开。

这一回弹过程会在引脚上产生密集的脉冲跳变，即机械抖动。常规轻触按键的
抖动持续时间一般在 5 ms 至 20 ms 之间。

单片机执行速度极快（每个循环微秒级），如果不消除抖动，单次物理按下操作
会被单片机判定为数十次连续按键动作，引发分拣计数暴增或执行机构误触发。

软件消抖是解决该问题最经济高效的手段，主要分为两类算法：
1. 延时确认法：初次检测到目标电平后，调用 delay(10) 到 delay(20) 延时避开
   机械抖动窗口期，再次读取引脚电平；若仍为目标电平，则确认为真实按下。
2. 周期连续采样法：在无阻塞轮询中固定周期（如每 5 ms）采样引脚电平，
   仅当连续 N 次（如 3 次）采样结果完全一致时，才更新系统认定的稳定按键状态。

### 例题
分拣工位安装了一个急停复位按键（接在引脚 2，低电平有效）。
请使用延时确认法编写一段检测逻辑，确保有效过滤机械抖动，
并在确认按下后仅调用一次 resetAlarm() 函数。

解答：
检测到首次 LOW 后延时 15 ms 跳过抖动期，再次确认仍为 LOW 则确认为有效动作，
并通过等待按键释放防止长按重复触发。
```c
void loop() {
  if (digitalRead(2) == LOW) {
    delay(15);                     // 延时 15 ms 避开机械触点抖动窗口
    if (digitalRead(2) == LOW) {   // 再次核验引脚电平
      resetAlarm();                // 确认有效触发，执行复位
      while (digitalRead(2) == LOW); // 阻塞等待操作员松开按键
    }
  }
}
```

### 常见错误
1. 消抖延时时间过短（例如小于 2 ms），未能完全跨过机械弹片物理回弹窗口。
2. 消抖延时过长（例如超过 200 ms），导致按键手感严重迟钝，甚至丢失快速触发。

## 边沿检测与事件计数
稳态电平（Level）与瞬态边沿（Edge）具有本质区别：电平是引脚在某一时刻
持续保持的逻辑状态；而边沿是信号电平发生跃变的历史瞬间。

工件通过到位对射光电传感器时，遮挡时间可能持续数百毫秒（持续低电平稳态）。
若直接使用 if (state == LOW) { count++; } 进行统计，主循环在遮挡期间会重复
执行成千上万次，导致计数失控。因此，工件到达事件必须依据电平跃变的瞬间判定。

边沿跳变分为两种类型：
1. 下降沿（Falling Edge）：引脚由 HIGH 跃变至 LOW 的瞬间（工件遮挡或按键按下）。
2. 上升沿（Rising Edge）：引脚由 LOW 跃变至 HIGH 的瞬间（工件离开或按键释放）。

边沿检测的核心在于维持历史状态变量 lastState：
- 判定下降沿：lastState == HIGH && currentState == LOW
- 判定上升沿：lastState == LOW && currentState == HIGH
每次循环处理完毕后，必须执行 lastState = currentState 更新历史状态。

### 例题
桌面分拣站流水线上的光电传感器接在引脚 7（工件遮挡输出 LOW，平时为 HIGH）。
请编写完整的边沿检测逻辑，每当有新工件到达检测位时，将变量 passCount 加 1。

解答：
工件到达对应信号由 HIGH 到 LOW 的下降沿跃变。通过比较当前状态与上一轮状态，
仅在下降沿成立的单次循环中增加计数。
```c
int lastState = HIGH; // 记录上一轮循环引脚电平
int passCount = 0;   // 工件通过计数器

void loop() {
  int currentState = digitalRead(7);
  // 检测到下降沿：前一刻为高，当前刻为低
  if (lastState == HIGH && currentState == LOW) {
    passCount++; // 瞬态事件触发，工件计数仅自增一次
  }
  lastState = currentState; // 务必在循环末尾刷新历史状态
  delay(10); // 周期延时兼顾轻微抖动滤波
}
```

### 常见错误
1. 遗漏末尾的 lastState = currentState 状态同步，导致边沿判定退化为持续电平判断。
2. 误用上升沿条件判断工件到达，导致在工件离开传感器遮挡区的瞬间才触发计数。

## 单元小结
1. GPIO 引脚作为输出时须通过限流电阻控制电流，拉电流与灌电流对应不同的导通电平。
2. GPIO 引脚作为输入时绝不可悬空，利用内置上拉电阻与接地按键构成低电平有效电路。
3. 机械弹性触点具有 5–20 ms 的固有回弹抖动，必须借助延时或多周期采样软件滤波。
4. 稳态电平反映引脚当前状态，边沿跃变反映事件发生瞬间；引入历史状态比对可实现单次计数。
