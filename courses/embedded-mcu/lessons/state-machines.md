# 状态机与可靠性

本单元面向桌面分拣工位项目，系统学习嵌入式有限状态机规范、异常与故障安全处理机制、以及硬件看门狗的配置与复位诊断技术。

## 本单元知识点

- 状态、事件与转移表：使用枚举与 switch-case 实现状态机，掌握状态转移表与进入动作。
- 故障状态与人工复位：监控超时与运行异常，进入故障安全状态并实现人工闭环复位。
- 看门狗与复位原因：配置片上独立硬件看门狗防止程序死锁，读取复位寄存器诊断停机源。
- 实作：四状态分拣工位（自评）：综合实现待机、检测、分拣与故障四状态工位控制程序。

## 状态、事件与转移表

有限状态机（Finite State Machine, FSM）是嵌入式系统组织复杂时序与多任务行为的核心架构。
状态机包含四个要素：状态（State，系统所处的确定运行模式）、事件（Event，触发状态改变的外部
输入或时序信号）、转移条件（Transition Condition，判断是否切变状态的逻辑表达式）与
动作（Action，状态切变或维持状态时执行的业务操作）。

在 C 语言中，推荐使用 enum 枚举类型明确列出所有互斥状态，禁止使用多个离散布尔变量表示状态，
以杜绝多状态重叠冲突。主循环 loop() 中通过 switch(currentState) 分流处理各状态的业务，
每个 case 内部依据事件与条件推进流转，且每个 case 必须以 break 显式终结。

状态转移表（State Transition Table）是状态机设计的核心工具。在编码前以二维表格形式详尽罗列
“当前状态、输入事件、转移条件、下一状态、执行动作”，可全面覆盖所有可能分支，避免遗漏边界逻辑。

进入动作（Entry Action）指系统切入新状态的那一瞬间仅执行一次的操作（如重置计时器、设置引脚电平）。
在代码中，应通过状态切换包装函数统一维护进入动作，避免在循环体内重复执行本应单次触发的初始化操作。

### 例题

题目：分拣工位包含待机（STATE_IDLE）和检测（STATE_WAIT）两个状态。工件触发到位传感器
（低电平有效）时切入 STATE_WAIT，并在进入瞬间记录进入时刻用于后续超时判断。请编写状态枚举定义
及状态转移处理函数。

解答：
```c
enum StationState { STATE_IDLE, STATE_WAIT };
StationState curState = STATE_IDLE;
unsigned long stateEnterTime = 0;

void changeState(StationState nextState) {
  curState = nextState;
  if (curState == STATE_WAIT) {
    stateEnterTime = millis(); // 进入动作：记录切入时间戳
    Serial.println("EVENT:ENTER_WAIT");
  }
}

void updateStateMachine() {
  switch (curState) {
    case STATE_IDLE:
      if (digitalRead(PIN_SENSOR) == LOW) {
        changeState(STATE_WAIT);
      }
      break;
    case STATE_WAIT:
      break;
  }
}
```

### 常见错误

- 状态组合爆炸：使用多个独立 bool 变量标记状态，导致出现两个变量同时为 true 的非法并存局面。
- 重复触发进入动作：将本应在切入状态时仅执行一次的外设驱动操作直接写在 loop() 的 case 内部，
  导致每个循环周期反复刷新。
- switch 穿透：在 switch-case 语句中遗漏 break 关键字，导致执行完当前状态代码后直接穿透执行下一状态代码。

## 故障状态与人工复位

故障处理是工业与桌面控制系统可靠性设计的底线。桌面分拣工位在实际运行中，可能遭遇工件机械卡死、
通信电缆脱落、视觉识别无响应等异常。系统必须具备专用的故障状态（FAULT），对所有预期外的超时
与硬件信号失常进行集中捕获与接管。

故障触发源通常包含两类：一是基于非阻塞计时的动作或通信超时（例如向电脑发送质检请求后，
超过指定时限仍未收到应答）；二是互斥传感器的非法逻辑组合（例如推料机构的前限位与后限位同时触发）。

故障安全原则（Fail-Safe）：系统进入 FAULT 状态瞬间，必须立刻将所有外部执行机构置于受控的安全状态。
例如立即切断推料机构动力、将舵机复位至中立安全位或停止输出 PWM，同时点亮红色故障指示灯并向串口
按节流间隔输出警报。严禁在故障状态下保持先前的执行器输出，防止电机堵转烧毁。

故障锁存与人工复位：系统一旦切入 FAULT 状态，必须进行状态锁存。严禁使用软件定时器在几秒后
自动清除故障自愈，因为物理卡料或通信断开无法通过软件重启消除。必须由操作人员现场排查解决问题后，
手动按下实体的复位按键（或上位机下发受控复位命令），状态机才允许转移回待机状态（IDLE）。

### 例题

题目：分拣工位在等待电脑视觉判定的 STATE_WAIT 状态下，若超过 3000 ms 仍未收到有效串口数据，
系统应转移至 STATE_FAULT。进入故障后关断舵机控制引脚，且只有在检测到人工复位按键（PIN_RESET 为低电平）
按下时才恢复待机。请给出该状态处理逻辑。

解答：
```c
enum StationState { STATE_WAIT, STATE_FAULT, STATE_IDLE };
StationState curState = STATE_WAIT;
unsigned long waitStartTime = 0; // 进入 STATE_WAIT 时应更新为 millis()

void handleFaultState() {
  switch (curState) {
    case STATE_WAIT:
      if (millis() - waitStartTime >= 3000) {
        curState = STATE_FAULT;
        digitalWrite(PIN_SERVO_EN, LOW); // 故障安全：关断执行器
        digitalWrite(PIN_RED_LED, HIGH); // 声光报警
        Serial.println("ERR:TIMEOUT_FAULT");
      }
      break;
    case STATE_FAULT:
      // 故障锁存：必须等待实体人工按键按下才可恢复
      if (digitalRead(PIN_RESET) == LOW) {
        digitalWrite(PIN_RED_LED, LOW);
        curState = STATE_IDLE;
        Serial.println("EVENT:MANUAL_RESET_OK");
      }
      break;
  }
}
```

### 常见错误

- 故障自动盲目自愈：认为异常只是暂时的，在故障状态中依靠软件延时自动恢复运行，
  导致机械在卡料未排除情况下强行通电受损。
- 遗漏安全输出：切入故障状态时仅设置了内部变量或打印了日志，未及时对舵机、电机等输出引脚
  实施断电或安全归位。
- 允许外部新事件打断故障：在 FAULT 状态下仍响应新工件的到位检测信号，导致未排故即被动开启下一轮作业流程。

## 看门狗与复位原因

看门狗定时器（Watchdog Timer, WDT）是单片机片上集成的独立硬件定时器，通常使用片内独立的 RC 振荡器
作为时钟源（如 AVR）。其核心使命是防止系统死锁：在主程序正常运行时，软件必须在看门狗计数溢出前向特定寄存器
写入指令将其计数器清零（俗称“喂狗”）；若程序陷入死循环或跑飞导致未能按时喂狗，硬件将强制触发单片机复位重启。

喂狗必须遵循“主流程畅通才喂狗”原则。喂狗语句必须置于主循环 loop() 正常轮询的主干路径上。
严禁将喂狗函数写入定时器中断服务函数（ISR）或延时函数内部——因为即使主循环已彻底死锁，
硬件中断通常仍会继续周期性触发并喂狗，导致看门狗彻底沦为摆设。

看门狗超时周期必须结合主循环最恶劣工况进行计算。先测定主循环遍历所有最耗时分支（如完整传感器采样、
复杂数据校验、执行器刷新等）的总时间上限 T_max，看门狗超时时间通常应配置为 2 至 4 倍的 T_max（取芯片支持的最接近档位，
如 AVR 提供 120 ms、250 ms 等档），
既保证主循环异常卡死时能尽快复位，又避免偶发任务延时造成误复位。

读取复位原因：单片机内部包含专门记录系统启动来源的复位状态寄存器（如 AVR 单片机的 MCUSR）。
该寄存器包含上电复位（PORF）、外部引脚复位（EXTRF）、看门狗复位（WDRF）等标志位。
在 setup() 函数最前端读取并清零该寄存器（部分引导程序会先清除它，
以所用板卡的文档为准），可将复位原因输出至串口日志，为远程运维与离线故障诊断提供第一手关键证据。

### 例题

题目：某分拣系统主循环中，传感器滤波耗时 10 ms，协议解析耗时 20 ms，舵机控制耗时 15 ms。
系统最差工况运行时间为三者之和。若看门狗周期设定为主循环最差耗时的 3 倍，求看门狗超时时间；
并在系统 setup() 中实现读取复位状态寄存器判断是否为看门狗复位的代码框架。

解答：
最差耗时计算：T_max = 10 ms + 20 ms + 15 ms = 45 ms。
看门狗超时时间：T_wdt = 45 ms * 3 = 135 ms。
代码实现框架（以典型 AVR 架构单片机为例）：
```c
#include <avr/wdt.h>

void checkResetSource() {
  uint8_t resetFlags = MCUSR; // 读取硬件复位状态寄存器
  MCUSR = 0;                  // 及时清零，避免影响下次判断
  wdt_disable();              // 复位后优先关闭看门狗
  if (resetFlags & (1 << WDRF)) {
    Serial.println("BOOT:WATCHDOG_RESET"); // 看门狗异常溢出复位
  } else {
    Serial.println("BOOT:NORMAL_RESET");   // 上电或人工按键复位
  }
}
```

### 常见错误

- 中断服务函数中盲目喂狗：在定时器中断 ISR 中周期喂狗，导致主循环陷入死循环后系统依旧无法复位。
- 看门狗阈值过小：未评估主循环最大耗时，盲目设置过小的看门狗超时时间，导致正常处理长数据包时触发意外误复位。
- 启动后未清除复位标志：在 setup() 中未及时清零复位状态寄存器，导致后续多次复位时历史标志位持续残留，误导诊断。

## 实作：四状态分拣工位（自评）

目标：
构建一套完整的四状态桌面质检分拣控制程序，将到位检测、非阻塞通信超时、舵机分流及安全故障保护整合为高可靠性的状态机闭环系统。

材料或准备：
单片机开发板、到位光电传感器（或按键模拟）、分拣控制舵机（PWM 输出）、状态指示灯（红绿双色）、
实体人工复位按键、电脑串口调试助手。

步骤：
1. 建立工程并定义四状态枚举：STATE_IDLE（待机）、STATE_WAIT_INSPECT（等待质检）、STATE_SORTING（执行分拣）、
   STATE_FAULT（故障保护）。
2. 在 setup() 中配置各引脚模式，初始化串口为 9600 波特率，将舵机归位至中立通道，红灯熄灭、绿灯点亮表示待机。
3. 实现 STATE_IDLE：轮询检测工件到位信号（低电平），触发后向串口发送质检请求帧 "REQ:CHECK\n"，
   记录当前时间戳并转移至 STATE_WAIT_INSPECT。
4. 实现 STATE_WAIT_INSPECT：使用 millis() 监控等待耗时。若 now - start < 3000 ms 内收到 'P'（合格）
   或 'F'（不合格），记录判定结果并转入 STATE_SORTING；若 now - start >= 3000 ms 仍未收到回复，转入 STATE_FAULT。
5. 实现 STATE_SORTING：根据判定结果驱动舵机转向合格箱（如 45 度）或不合格箱（如 135 度），非阻塞计时等待工件滑落（1000 ms）
   后将舵机回位至中立角（90 度），并返回 STATE_IDLE。
6. 实现 STATE_FAULT：进入时关闭舵机输出，常亮红灯并向串口输出报警信息；屏蔽到位信号，仅当按下专用实体人工复位按键后熄灭红灯并返回 STATE_IDLE。

### 自评清单

- [ ] 工件到位后能稳定切入等待质检状态，并向串口发送质检请求与正确记录时间戳。
- [ ] 接收到上位机合格或不合格指令后，舵机能正确转至对应角度，延时后归位并返回待机。
- [ ] 当上位机断开无应答时，系统在 3000 ms 超时后准确切入故障状态，舵机断电/归位且红灯报警。
- [ ] 处于故障状态下，放入新工件不会被误触发，必须按下实体人工复位键后系统才恢复正常待机。

## 单元小结

- 有限状态机通过状态枚举、switch 分流与状态转移表，有效避免了嵌入式代码中的零散标志位与时序混乱。
- 状态的进入动作由专有包装函数在切变瞬间单次触发，确保外设初始化与计时基准只在切入时设置一次。
- 故障状态坚持“故障安全”与“人工复位”双重保障，杜绝机械卡料或通信失步状态下的盲目自动带病运转。
- 看门狗依靠片上独立硬件定时器防范死锁跑飞，必须在主循环主干喂狗，并结合复位寄存器实现运行故障的精准溯源。
