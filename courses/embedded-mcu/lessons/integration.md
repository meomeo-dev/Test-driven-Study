# 系统集成与测试

本单元学习桌面质检分拣站的软硬件系统集成与测试方法，掌握引脚规划、信号滤波、分步联调及上电安全机制。

## 本单元知识点
- 需求与 IO 分配表：梳理输入输出电气需求，明确引脚、电平、上下拉与安全默认值。
- 传感器滤波与迟滞：应用均值、中值滤波与迟滞双阈值消除毛刺与乒乓抖动。
- 分模块联调与测试记录：遵循自底向上原则分步调试，规范设计测试用例与预期。
- 上电、掉电与安全默认状态：掌握复位瞬间引脚行为、安全初始化顺序与掉电防护。

## 需求与 IO 分配表
在嵌入式系统软硬件联调前，必须建立规范的《IO 分配表》。它是硬件接线与底层
驱动程序之间的工程契约，能够有效避免引脚功能冲突与电气损坏。

编制 IO 分配表的核心要素包括：
- 信号名称与外设功能：清晰标注外设信号的实际作用（如到位检测、舵机控制）。
- 引脚编号与电气方向：区分微控制器的物理引脚（如 D2、A0），标明输入或输出。
- 电平类型与上下拉模式：针对开集/开漏信号（如 NPN 开关）配置内部上拉模式
  （INPUT_PULLUP），杜绝输入引脚悬空引入的电磁杂波干扰。
- 安全默认状态：明确在上电复位和待机时引脚的默认输出电平或舵机角度。

引脚分配规划准则：优先预留硬件专用功能引脚。硬件串口 TX/RX（如 D0/D1）常用于
程序烧录与运行监控，切忌分配给普通开关或执行器；PWM 输出应分配在具备硬件
定时器比较通道的引脚上；模拟电压信号必须连接至具有 ADC 功能的模拟引脚。

### 例题
【背景】桌面质检分拣站包含以下外设：到位检测光电开关（常开 NPN，工件遮挡时输出
接地低电平）、合格指示灯（高电平点亮）、不良指示灯（高电平点亮）、复位按键
（常开微动开关，按下时接地）、分拣挡板舵机（PWM 脉宽控制）、电脑串口通讯。
【要求】列出该系统的核心 IO 分配表，并说明各引脚的模式与安全默认状态。
【解答】
1. 核心引脚分配设计：
   - 到位传感器：D2，数字输入，配置 pinMode(2, INPUT_PULLUP)，默认检测到高电平。
   - 复位按键：D3，数字输入，配置 pinMode(3, INPUT_PULLUP)，默认检测到高电平。
   - 合格指示灯：D4，数字输出，配置 pinMode(4, OUTPUT)，安全默认输出 LOW（熄灭）。
   - 不良指示灯：D5，数字输出，配置 pinMode(5, OUTPUT)，安全默认输出 LOW（熄灭）。
   - 分拣舵机：D9（硬件 PWM 引脚），数字输出，安全默认输出 90 度中位脉冲。
   - 电脑通信：D0(RX)/D1(TX)，专用 UART 引脚，由 Serial.begin(9600) 统一初始化。
2. 安全分析：NPN 开关与按键均采用内置上拉，避免未触发时引脚悬空受到工频干扰；
   指示灯和舵机在上电瞬间锁定在熄灭与中立导向位置，确保机械机构不发生碰撞。

### 常见错误
1. 浮空输入未上拉：输入引脚未启用内部或外部偏置电阻，导致工件未到位时引脚电平随机跳变。
2. 误占串口引脚：将普通按键或舵机分配到 D0 或 D1 引脚，导致程序无法正常烧录或串口输出乱码。
3. 忽略执行器初态：未在文档中规定复位初态，程序启动瞬间执行器产生不可控的飞车动作。

## 传感器滤波与迟滞
在工业分拣现场，传感器采集的电信号往往混杂有机械微振动、供电纹波以及电机启闭
产生的电磁尖峰。若将未经滤波的原始信号直接送入状态机，必然引发频繁误动作。

常用滤波算法及适用场景：
- 算术平均滤波：在滑动窗口内对 N 次采样值求平均，能有效压制高斯白噪声。但 N 过大
  会引入显著的时间相位滞后，导致快速移动的工件被漏检。
- 中值滤波：对滑动窗口内的连续 N 次采样按数值升序排序，取正中间的中位数输出。
  该算法能有效剔除偶发的脉冲电火花与孤立尖峰，且不拉偏基线均值。

阈值迟滞（双阈值）防抖原理：
当模拟量在判定阈值附近缓慢变化或叠加高频纹波时，单一阈值会导致判定结果在
0 与 1 之间高频抖动，产生乒乓效应。迟滞比较通过引入高低双阈值消除该现象：
- 高阈值（V_high）：信号由低往高上升时，必须越过 V_high 才置为“有工件”。
- 低阈值（V_low）：信号由高往低回落时，必须跌破 V_low 才判定为“工件离开”。
回差电压 ΔV = V_high - V_low 必须大于现场噪声的峰峰值，从而实现软件电气防抖。

### 例题
【背景】分拣站采用模拟测距传感器检测工件厚度。无工件时采样电压约为 1.0 V，工件到达
后电压升至 3.6 V，信号上叠加了峰峰值约 0.4 V 的高频杂波。
【要求】设计迟滞双阈值并写出避免乒乓抖动的 Arduino 判定代码（10 位 ADC，5 V 参考）。
【解答】
1. 阈值计算与选型：设定低阈值 V_low = 1.8 V，高阈值 V_high = 2.6 V。迟滞回差
   ΔV = 2.6 V - 1.8 V = 0.8 V，显著大于 0.4 V 的噪声幅度。
   对应 10 位 ADC 计数值（max 取 1023）：
   ADC_low = (1.8 / 5.0) * 1023 ≈ 368；
   ADC_high = (2.6 / 5.0) * 1023 ≈ 532。
2. 迟滞判定核心代码实现：
```c
static bool item_detected = false;
int raw_adc = analogRead(A0);
if (!item_detected && raw_adc > 532) {
  item_detected = true;
} else if (item_detected && raw_adc < 368) {
  item_detected = false;
}
```

### 常见错误
1. 单阈值误判：仅使用单一固定阈值比较模拟量，在临界位置导致状态机频繁触发到位事件。
2. 滤波窗口过大：平均滤波采样点数设定过多，滤波滞后时间超过工件通过工位的时间窗口。
3. 迟滞区间过窄：设定的回差电压小于现场噪声峰峰值，无法有效阻止输出抖动。

## 分模块联调与测试记录
系统集成绝不能在装配完成后直接烧录完整总程序进行“盲调”。一旦出现执行器不动作，
将无法定位是传感器失效、机械卡阻、串口丢包还是状态机死锁。

自底向上的分模块联调规范：
1. 单元测试阶段：编写独立的最小测试固件，单独测试数字与模拟输入是否灵敏可靠、
   单独测试舵机旋转特定角度是否精准、单独测试串口数据帧收发是否正常。
2. 接口与子系统联调：将输入传感器与主状态机联调（验证事件触发），随后将状态机
   与串口通信协议联调（验证握手、校验与超时重试机制），最后接驳执行器。
3. 整机闭环系统测试：加载全功能程序，在真实流水作业工况下开展全流程综合验证。

规范化测试用例与记录：测试用例必须包含前置条件、输入激励、预期行为与实测结果。
除验证正常的分拣流程外，必须强制设计异常与容错用例（如工件到位后电脑断线超时、
接收乱码指令、连续工件堆叠等），检验系统的异常捕获与故障安全转移能力。

### 例题
【背景】分拣站单片机检测到工件后通过串口发送 CHECK\n 请求，上位机应在 500 ms 内
回复 PASS\n 或 FAIL\n。若上位机超时未回复，单片机应进入 FAULT 故障状态。
【要求】设计一份用于验证该“通信超时安全保护”功能的工程测试用例记录。
【解答】
- 用例编号：TC-INTEG-COMM-02
- 测试项目：质检请求超时无响应容错测试
- 前置条件：分拣工位上电就绪，状态机处于 IDLE 状态，串口波特率配置为 9600
- 测试步骤：
  1. 人工放入测试工件触发到位检测传感器；
  2. 捕获单片机串口输出，确认发出 CHECK\n 请求数据帧；
  3. 上位机模拟软件保持静默，不返回任何响应报文；
  4. 监测单片机在 500 ms 超时后的行为响应与外设状态。
- 预期结果：单片机在第 500 ms 起判定超时，故障指示灯亮起，分拣舵机保持安全中位，
  向上位机回传 ERR_TIMEOUT\n 日志，主状态机转移至 FAULT 故障保护状态；判定时刻允许误差为 +20 ms。
- 实测记录与结论：单片机在 501 ms 时触发报警，所有动作符合预期，测试通过（PASS）。

### 常见错误
1. 跨阶段调试：跳过底层输入输出单测直接运行完整控制逻辑，导致连线松动被误判为软件死锁。
2. 预期结果模糊：测试记录仅填写“动作正常”“大致良好”，缺乏可客观核对的数值指标与电平状态。
3. 忽略容错测试：仅测试合格品与不良品的常规流程，未对断线、协议乱码等异常边界做充分验证。

## 上电、掉电与安全默认状态
单片机从通电起振到开始执行用户 setup() 代码之间，存在数毫秒到数十毫秒的硬件启动
时间。在此启动窗口内，绝大多数微控制器的所有 GPIO 引脚硬件默认处于高阻输入
（High-Z）状态（部分芯片的个别引脚带有默认上下拉，如 ESP32 的启动配置
引脚，须查阅芯片手册）。

软硬件协同的安全启动设计：
- 硬件电平偏置：对于控制电机、继电器或 MOS 驱动器的开关引脚，外部硬件电路必须
  配置上拉或下拉电阻固定安全电平，防止高阻浮动态下功率外设误导通。
- 软件初始化顺序：在 setup() 函数内部，必须最优先将执行器控制引脚配置为 OUTPUT，
  并立刻输出安全静止电平；随后再初始化传感器引脚、开启串口以及执行校准延时。

掉电与复位恢复机制：
当发生供电跌落（Brown-out）或看门狗溢出复位时，单片机 RAM 内存变量全部丢失，工件
的实际物理位置与机械当前姿态已经脱离软件控制。系统复位启动后严禁盲目从断电前
的位置继续分拣，必须强制状态机进入安全初始状态（如待机，或等待人工确认的故障状态），
关闭执行器并等待基线校准。

### 例题
【背景】某初学者编写的桌面分拣站程序，在开机瞬间舵机挡板总会出现剧烈抽动并撞击
机械限位。排查发现其 setup() 函数首先执行了 delay(2000) 等待电源稳定，并打印了
大量调试字符，最后才对舵机引脚进行 pinMode 与脉宽初始化。
【要求】分析该问题的产生机理，并给出符合工业安全规范的 setup() 架构代码。
【解答】
1. 故障原因：单片机引脚上电后处于高阻浮动态，长时间无稳定控制信号导致舵机驱动板
   受到悬空杂波激励产生飞车抽动；延时 2 秒与串口输出进一步延长了失控时间。
2. 规范的 setup() 安全初始化架构：
```c
#include <Servo.h>
Servo servo;

void setup() {
  // 1. 第一时间锁定执行器引脚至安全默认状态
  servo.attach(9);
  servo.write(90); // 立即输出 90 度安全中立位脉宽
  pinMode(4, OUTPUT);
  digitalWrite(4, LOW); // 熄灭指示灯
  // 2. 初始化输入传感器引脚
  pinMode(2, INPUT_PULLUP);
  // 3. 最后启动通信总线与状态机
  Serial.begin(9600);
  system_state = STATE_IDLE;
}
```

### 常见错误
1. 滞后初始化执行器：在 setup() 中先执行大量延时或复杂计算，使执行器在浮动态下失控停留。
2. 掉电盲目续跑：掉电复位后直接跳过机械原点标定，导致执行机构与实际工件位置错位损坏。
3. 依赖纯软件保护：忽略了单片机复位瞬间的引脚高阻特性，省略外部硬件下拉保护电阻。

## 单元小结
- 需求与 IO 分配表是系统集成的工程基石，必须详细定义每个引脚的模式、电平及安全默认状态。
- 传感器采集应组合使用中值滤波与均值滤波压制噪声，并依托迟滞双阈值消除信号临界抖动。
- 系统联调坚持自底向上的原则，先分别单测输入、输出与通信，再通过完整用例集验证整机逻辑。
- 软硬件结合构建上电与掉电安全屏障，setup() 须优先锁定执行器初态，故障复位后强制归零。
