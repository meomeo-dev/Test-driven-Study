# 上线验收

本单元学习如何在桌面分拣站评估推理耗时与吞吐量、使用未参与调参的全新批次完成
模型与规则法的对比验收，并在上线后监控数据漂移与建立复检闭环。

## 本单元知识点
- 处理耗时与吞吐：单件全流程耗时、节拍与吞吐量计算，平均与长尾耗时评估及高精度计时。
- 独立批次验收：未参与训练的新批次准入验证、与规则法对比及预设冻结准入指标。
- 数据漂移与监控：环境光照与来料变化导致的数据漂移、日常监控指标与复检闭环。
- 规则法与模型对比验收（自评）：实机采集独立批次并比对双法漏检率、误剔率与耗时。

## 处理耗时与吞吐
工业桌面质检分拣站中，工件经由输送带通过检测工位。到位传感器检测到工件后触发
相机曝光，视觉系统完成图像预处理与模型推理，并向 PLC 或单片机发送判定信号，
最后由气动推杆或挡板将工件分选至合格或不合格料盒。

单件处理耗时（Latency）指从触发信号输入到分拣控制信号输出的端到端全流程耗时。
生产节拍（Cycle Time）是流水线允许单件占用的最大时间窗口。系统的端到端最坏
情况耗时必须小于动作时间窗口扣除机械动作延时后的净裕量，否则挡板动作滞后将
导致漏分拣。吞吐量（Throughput）表示单位时间内系统稳定处理的工件数，例如件/分钟，
受限于整个流程中最慢的瓶颈子环节。

在评估算法耗时时，不能只看平均耗时（Mean Latency），必须重点关注长尾耗时（如
P95、P99 或最大耗时）。由于操作系统线程调度、内存垃圾回收或复杂图像边缘特征
提取的计算波动，单件耗时可能出现突发峰值。若 P99 耗时突破机械动作窗口，意味着
产线上有 1% 的工件会发生分拣失步故障。

代码计时应使用 Python 的高精度单调时钟 time.perf_counter()。正式测试前必须输入
若干张工件图像进行预热（Warm-up），排除深度学习框架初始化、权重加载与动态内存
分配造成的冷启动延迟，随后统计连续多件运行的平均值、标准差与高分位数。

```python
import time

# 预热后使用高精度单调时钟统计稳态推理耗时
start_time = time.perf_counter()
pred = model.predict(preprocessed_img)
latency_ms = (time.perf_counter() - start_time) * 1000
```

### 例题
某桌面分拣站流水线要求吞吐量不低于 60 件/分钟。工件触发光电传感器后在传送带上
运行 1.2 秒到达分拣挡板位置。已知气动挡板推出动作需要 0.3 秒，相机图像采集与
传输耗时 0.2 秒，通信延迟为 0.1 秒。现测试轻量分类模型，预热后测得平均推理耗时
为 0.4 秒，P99 耗时为 0.55 秒，最大耗时为 0.65 秒。请问：
1. 留给模型推理的最大允许耗时为多少秒？
2. 该模型的最坏情况耗时是否满足生产节拍与动作时间窗口要求？
解答：
1. 动作窗口总时间为 1.2 秒。扣除机械动作 0.3 秒、采集传输 0.2 秒及通信 0.1 秒，
留给模型推理的最大允许耗时 = 1.2 - 0.3 - 0.2 - 0.1 = 0.6 秒。
2. 吞吐量 60 件/分钟对应平均单件周期为 60 / 60 = 1.0 秒。虽然平均推理耗时 0.4 秒
小于 0.6 秒且平均节拍达标，但测得最大单件耗时达到 0.65 秒，突破了 0.6 秒的窗口上限。
在极端峰值耗时下挡板将无法及时推出，因此最坏情况不满足准入要求，需进一步优化。

### 常见错误
1. 直接使用 time.time() 并在未预热状态下记录单次运行耗时，将冷启动时间误当稳态性能。
2. 仅以平均耗时达标作为验收准则，忽视 P99 或最大长尾延迟超标导致的偶发性漏动作。

## 独立批次验收
独立批次验收是指在模型正式投产前，采用在时间和批次上完全崭新、从未参与过前期
特征工程、模型训练、验证集选择及超参数调节的实物工件进行最终准入测试。

在模型研发迭代阶段，即便保留了离线验证集，开发者在反复调整网络结构、数据增强
强度和判决阈值的过程中，验证集信息已被隐式利用，极易造成评估性能偏高。独立批次
提供了与实际工况完全一致的无偏评估基准。

在实务中，新模型必须与现存基准（如原有尺寸与灰度规则法）在同一批独立工件上并行
测试，并以人工质检确认的真实物理状态作为金标准。统一约定缺陷为正类：
```
漏检（FN）：实际为缺陷，被系统判为良品放行（造成质量事故与客诉风险）
误剔（FP）：实际为良品，被系统判为缺陷推入废料盒（造成材料浪费与返工成本）
漏检率 = FN / (TP + FN)
误剔率 = FP / (FP + TN)
```

验收指标门槛（如漏检率 ≤ 1.0%，误剔率 ≤ 3.0%）必须在测试前以技术契约形式预先
冻结。严禁在测试后根据模型输出临时调宽门槛，或随意微调判决阈值掩盖缺陷。由于
不良品流出将引发重大质量损失，工业质检通常将漏检率列为一票否决的核心红线。

### 例题
质检站对 500 件全新独立工件进行并行验收，人工金标准确认其中有 50 件缺陷品与
450 件良品。测试记录显示：
规则法：检出 40 件缺陷（其中 38 件为真缺陷），误将 2 件良品判为缺陷。
新模型：检出 52 件缺陷（其中 48 件为真缺陷），误将 4 件良品判为缺陷。
若产线准入标准为“漏检率 ≤ 5.0%，误剔率 ≤ 2.0%”，请计算两者的漏检率与误剔率，
并给出上线决策。
解答：
实际缺陷数 TP + FN = 50，实际良品数 FP + TN = 450。
1. 规则法：
TP = 38，FN = 50 - 38 = 12；FP = 2，TN = 450 - 2 = 448。
漏检率 = 12 / 50 = 24.0%；误剔率 = 2 / 450 ≈ 0.44%。
2. 新模型：
TP = 48，FN = 50 - 48 = 2；FP = 4，TN = 450 - 4 = 446。
漏检率 = 2 / 50 = 4.0%；误剔率 = 4 / 450 ≈ 0.89%。
决策结论：
规则法漏检率高达 24.0%，严重突破 5.0% 的安全红线；新模型漏检率为 4.0% ≤ 5.0%，
误剔率为 0.89% ≤ 2.0%，两项关键指标均达到预设准入要求，批准新模型上线替代规则法。

### 常见错误
1. 使用曾用于超参数搜索的交叉验证集代替现场独立批次进行验收，产生过拟合虚假置信。
2. 看到独立测试指标未达标时，当场手动调整分类概率阈值迎合当前批次，破坏客观性。

## 数据漂移与监控
工业生产环境具有动态不确定性。模型上线后，输入图像特征分布可能因物理环境变动
发生偏离，即数据漂移（Data Drift），导致原本合格的模型分类性能显著下滑。

引发数据漂移的常见现场物理因素包括：
1. 光照漂移：车间环境光杂散干扰，或工位补光 LED 光源逐渐光衰导致图像对比度变差。
2. 材料漂移：上游供货商更换、原材料批次更替引起工件表面粗糙度、颜色或底纹变化。
3. 机构漂移：输送带长期机械振动导致相机安装支架微量松动，造成焦距模糊或视场偏移。

为了及时发现模型退化，必须建立多层级监控机制：
- 宏观过程监控：持续统计每班次或每日预测缺陷率占比。若该比率突变，预示环境漂移。
- 抽检复核机制：每日固定比例（如 5%）人工抽检分拣结果，统计实时漏检率与误剔率。
- 闭环处置：发现漂移超限后，采集新漂移样本由人工复核标注，扩充训练集进行微调，
并在新独立批次上重新通过验收门禁后，方可热更新部署。严禁直接采用模型伪标签无监督更新。

### 例题
某质检分拣站在更换车间照明后，连续两天单日检测的 1000 件工件中，模型判定的缺陷数
从历史平均的 30 件骤增至 120 件。质检员抽检这 120 件工件，发现仅有 28 件确为缺陷，
其余 92 件均为表面带有新灯具反射光斑的良品。请分析问题根源并说明规范处置步骤。
解答：
1. 问题根源：新照明灯具引入的杂散反射光斑改变了输入图像的特征分布，发生了典型的
协变量数据漂移（Covariate Shift），使模型误将光斑当作表面划痕，误剔率急剧恶化。
2. 处置步骤：
第一步，优先调整物理遮光罩或偏光镜以消除外界光源直射与光斑反射干扰；
第二步，若物理改善后仍存在特征偏差，现场采集包含新环境特征的工件图像并人工复验标注；
第三步，将带标签的新工件图像增量加入训练集重新微调，并在新的独立批次上验收通过；
第四步，确认误剔率恢复至受控指标范围后重新部署上线。

### 常见错误
1. 发现缺陷警报突增便误认为来料质量崩溃，未排查光学与机构环境是否发生物理漂移。
2. 直接使用模型自身的预测结果自动生成标签进行无监督再训练，导致伪标签放大误差。

## 规则法与模型对比验收（自评）
目标：在桌面质检分拣站实机上运行独立实物工件批次，同步记录真实结果、规则法判定
和模型判定，定量核算漏检率、误剔率与全流程处理耗时，完成标准化上线准入评估。

材料或准备：
1. 桌面质检分拣平台（到位光电传感器、相机、主控计算机、分拣挡板机构及控制程序）。
2. 未参与过模型前期训练与调优的全新实物工件至少 50 件（良品与各类典型缺陷工件都要有，缺陷件不少于 10 件）。
3. 待测规则法基线脚本、待验收模型推理程序以及 CSV 运行日志记录模板。

实施步骤：
1. 建立工件金标准：对独立批次中的所有工件进行编号，人工目检确认并记录真实状态。
2. 配置记录程序：在检测主控程序中配置数据记录器，保证每次触发均将工件 ID、真实
标签、规则法输出、模型预测值及端到端处理耗时（毫秒）追加写入 CSV 文件。
3. 执行实机过料：开启输送线，按编号顺序依次将工件送入夹具过检，观察挡板分拣动作。
4. 计算关键指标：读取 CSV 日志，分别计算规则法与模型的混淆矩阵、漏检率与误剔率，
并使用 numpy 分别统计规则法与模型的单件全流程平均处理耗时、P95 值与最大值。
5. 做出准入决策：将指标与预设标准（如漏检率 ≤ 2%、误剔率 ≤ 5%、P95 耗时 ≤ 300 ms）
逐项对照，写出“批准上线”或“驳回返工”（go/no-go）的结论及依据。

## 单元小结
- 质检模型上线不能只看离线准确率，必须在独立实物批次上以漏检率和误剔率双指标严格验收。
- 单件处理耗时需兼顾平均值与长尾延迟（P95/P99），确保端到端耗时在分拣动作窗口内留有裕量。
- 准入规则必须在验收启动前硬性冻结，严禁根据测试结果事后调整判决阈值或准入门槛。
- 工业现场环境易受光照、来料和振动扰动产生数据漂移，必须建立常态化统计监控与样本复检迭代闭环。
