# 各类专业软件的界面惯例（Professional Software Conventions）

执行到为某类专业软件选择布局变体、设计行情与交易类监控界面，或规划一次改版时加载。来源、
核验日期与复核期登记在 `index/knowledge-index.yaml` 的条目
`professional-software-conventions`；正文只写结论与可操作的事实。产品按类别描述。通用骨架
与各区域职责见 `layout-and-regions.md`。

## 1. 布局变体

| 变体 | 典型类别 | 适合 | 不适合 |
| --- | --- | --- | --- |
| 三栏主从（导航、列表、详情） | 邮件、文件管理、项目管理、团队通讯 | 逐条浏览并处理一批记录 | 同时比较多个对象 |
| 活动栏 + 侧边栏 + 编辑区 + 底部面板 | 代码编辑器、集成开发环境 | 多种文件与工具并存的长时间工作 | 视图少于三个时（活动栏与侧边栏合并为一条导航栏） |
| 按阶段分页（每页一个完整工作区，按流程从左到右） | 影音后期 | 流程固定、各阶段工具差异大 | 需要在阶段之间频繁往返 |
| 画布居中 + 停靠面板 | 协作设计、绘图 | 空间编辑 | 以表格与文本为主的任务 |
| 多面板网格（面板按标的联动，布局可保存可共享） | 金融终端、行情工具 | 同时监控多个数据源 | 单一高频流程 |

## 2. 金融终端与行情监控

- 按标的联动：面板分组，组内任一面板切换标的，同组面板跟随；常用颜色标记分组。
- 跨应用共享当前标的等上下文有开放标准 FDC3（核验时当前版本 3.0，2026-10-26 发布；context
  数据格式与 intent 都是标准的组成部分）；没有跨应用联动需求时不引入。
- 命令行式输入：输入代码或命令直接跳到对应功能；通用工具中由命令面板承担。
- 报价表与记录表（blotter）：一行一条报价或成交记录，列按标的、关键条款、来源、价格、时间
  组织；行高紧凑，数字右对齐。
- 新鲜度：同时显示绝对时间与相对时间（如「10:05 · 3 分钟前」）；过期数据降低对比并写明状态，
  仍满足对比度要求。只显示时间、不标过期，容易误取旧价。
- 数值变化时短暂闪烁或高亮后消退，时长约 300～500 ms（经验值，未核实）。
- 连接与会话状态用状态栏圆点加文字；告警进底部面板，并在状态栏计数。
- 深色主题适合长时间盯屏与高密度，彩色语义更突出（经验判断，未核实）；作为跟随系统的可选
  主题，不作为唯一主题。
- 红绿含义随市场不同：中国大陆等市场常为红涨绿跌，欧美市场常为绿涨红跌（惯例，未逐市场
  核实）。涨跌色需要可配置，并配合箭头或正负号；不表达涨跌的标记（如最优值）用强调色加粗
  加图标，不用红绿。
- 单屏用固定骨架；多显示器时允许面板浮出为独立窗口。

## 3. 改版的共同方向

各类专业软件的公开改版说明有共同方向：降低视觉噪声、渐进披露（progressive disclosure）、
让界面让位于内容、保护用户已有的操作习惯。按类别归纳：

| 类别 | 问题 | 做法 |
| --- | --- | --- |
| 集成开发环境 | 工具栏与工具窗口拥挤 | 降低视觉复杂度，核心功能易达，高级功能渐进展示；另提供紧凑模式与可自定义工具栏 |
| 协作设计工具 | 多年增量叠加后空间不足 | 以作品为中心，统一模式，保护肌肉记忆；默认浮动面板在测试中干扰日常流程，改回停靠面板 |
| 项目管理工具 | 视觉噪声、对齐不一、导航层级混乱 | 降噪、统一对齐、提高密度、统一页头与导航 |
| 团队通讯工具 | 功能增多后侧栏过载 | 窄主栏按工作模式分区，次级栏列出该模式下的条目 |
| 金融终端 | 功能持续增长，不能打断用户流程 | 隐藏复杂度而不是删除；每日小幅渐进改动；页面（组件集合）可在团队内共享 |
| 办公套件 | 功能区复杂 | 简化功能区并可展开为完整形态；桌面版推进保守 |
| 代码编辑器的扩展生态 | 扩展添加的视图过多 | 限制视图数量，能做成命令的不做成视图 |

- 一次大面积重做用户已经熟悉的操作是反模式；改版以渐进方式进行。
