# 宿主原语（Host Primitives）

执行到工作流第 0、4、5、6 步时加载：确认宿主能否承载 swarm、派发成员、挂事件监视、续接
成员。

本页是快照，核验于 2026-11-19，对象是 Claude Code 2.1.328 及其官方文档。宿主版本会漂移，
以当次的 `--help`、工具说明与官方文档为准。

## 1. 宿主能力

| swarm 机制 | 需要的宿主能力 | Claude Code 中的做法 |
| --- | --- | --- |
| 并行 worker | 在后台运行子代理，主会话不必等待 | Agent 工具，子代理在后台运行 |
| 唤醒 coordinator | 后台子代理结束运行时通知主会话 | Agent 工具自带完成通知；monitor 的 `stall` 另经 `watch` 推送 |
| 点名唤醒已结束的成员 | 向已结束的子代理发消息并续接其会话 | `SendMessage`，收件人写该子代理的 ID |
| monitor 定时巡检、成员待命 | 子代理内的有界等待 | `swarm-board.mjs wait`（Bash，单次调用 ≤ 600 秒） |
| 成员运行中把消息推给 coordinator | 主会话的事件监视：命令每输出一行就通知一次 | `Monitor` 工具挂 `swarm-board.mjs watch --for coordinator`，`timeout_ms` 1800000 |
| 共享消息板 | 所有成员能读写同一目录 | 子代理默认共享主会话的工作目录 |

“成员运行中把消息推给 coordinator”一项是可选能力，其余都是必需的：

- 没有事件监视时，coordinator 只在成员结束运行时收到通知。待命成员发出的 `done` 要等 monitor
  报 `unanswered`，或者等 coordinator 自己读板才能看到。所以没有事件监视的宿主上不开待命。
- monitor 的唤醒方式随之而定（提示词参数 `{{wake_by}}`）：有事件监视时取 `watch`，`stall`
  经 `watch` 推给 coordinator，monitor 报警后继续巡检；没有时取 `exit`，monitor 报警后发
  `done` 并结束运行，由结束通知唤醒 coordinator。

实测（2026-11-19）：

- 后台子代理能经 Bash 并发追加同一文件，没有出现交错写坏。
- 子代理内 Bash 有界轮询（单次调用内循环等待，timeout 590000 ms）没有被拒绝。
- `SendMessage` 续接后，成员保留了原来的上下文。
- 子代理结束运行时，主会话收到通知。
- 主会话的 `Monitor` 尾随看板文件，每出现一条匹配的记录就收到一条通知；不匹配的记录不
  触发通知。

## 2. 派发时的注意事项

- **不要给 Agent 调用传 `name`。** 环境设置了 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 时：
  - 交互会话里，带 `name`、非 fork、无 `isolation` 的调用会生成 teammate 而不是子代理，
    而且不询问用户。teammate 的通讯、完成通知与工具继承都和子代理不同。
  - `-p` 与 SDK 会话不生成 teammate。
- **续接 ID 留在会话里。** 子代理 ID 是续接所需的地址，coordinator 在会话中保存。不要写进
  板、派发书或任何可能提交的文件。
- **模型。** 默认让成员沿用主会话的模型。用户或项目规则指定了子代理模型时照办。
- **worktree 隔离。** `isolation: worktree` 从默认分支建 worktree，不从主会话当前的 `HEAD`
  建，落地合并也没有内建流程。只在用户明确要求时使用；默认共享工作目录，由派发书划定
  文件所有权。
- **权限。** 子代理受主会话权限模式约束。某个成员被拒绝的操作，不要转交另一个成员去做；
  交还用户决定。

## 3. 原生 agent teams 不能替代消息板

Claude Code 的 agent teams 是实验功能（`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`），与本
Skill 的消息板有以下差异：

- 只在交互会话生效；
- 通讯是点对点信箱，没有广播、序号与 channel；
- 一个会话只能有一个团队；
- 没有停滞监视。

本 Skill 不依赖它，也不要求开启它。

## 4. 已知限制

- **`Monitor` 工具。** 单次默认 5 分钟，最长 30 分钟，`-p` 下为 10 分钟。
  - 到时要重新挂上：`watch` 最后一行给出的 `--since` 保证不漏消息。
  - 输出过多的监视会被宿主停掉，所以 `watch` 只输出需要 coordinator 处理的消息。
  - 后台子代理内能否使用它尚未实测，monitor 成员与待命成员改用 `wait`。
- **会话内定时（`CronCreate`、`/loop`）。** 只在会话空闲时触发，非 `*/5` 的循环最多晚起
  所隔间隔的一半，7 天过期。不用它驱动 monitor。
- **运行中途的推送唤醒。** 向正在运行的成员发消息，要到它下一轮工具调用时才送达。
  本 Skill 不用这种推送：成员在 `wait` 或读板时看到发给它的消息；待命成员的 `wait` 一见到
  就返回。成员之间的 `handoff` 也按这条路径送达。

## 5. 其他宿主的降级

| 宿主情况 | 做法 |
| --- | --- |
| 宿主有原生 swarm（如 agy 的 `/swarm`） | 用宿主原生功能，不用本 Skill |
| 有子代理，但不能后台运行或没有完成通知 | 按期逐个以前台子代理运行成员，不派 monitor；消息板照常使用 |
| 不能续接已结束的子代理 | 修正项派给新成员 `<name>-2`，派发书引用原作者的产出与 `fix` 的 `#seq` |
| 没有子代理 | 不适用本 Skill，直接在主会话中完成工作 |
